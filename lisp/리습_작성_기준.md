# 리습 작성 기준 (캐드선수 하위 모듈, 2026-11-22)

캐드선수(`seonsu`, 저장소 `sbg3704/ClockOut-Lisp`)에 넣는 AutoCAD 리습을 사람과 AI가 같은 모양으로 만들기 위한 기준이다. 엑셀 추가기능 기준(칼퇴 `docs/03_매크로_제작_가이드.md`, 이 저장소 `addins/_common/README.md`)과 훈수꾼 모듈 기준(훈수꾼 `docs/07`, `docs/15`)에서 리습에 맞는 것만 가져와 고쳤다.

- 리습 소스는 **이 저장소에 넣지 않는다.** 원본 자리는 `ClockOut-Lisp/modules/lisp/<모듈id>/`이다. 이 문서는 규칙만 둔다(이 저장소 `.gitattributes`는 `*.lsp`를 CRLF로 바꾸므로 리습 파일을 여기 두면 바이트가 달라진다).
- 어긋나면 다음 순서로 이긴다: 사용자 결정(ClockOut-Lisp `docs/01` 2장) > 칼퇴 `docs/10`·`docs/11`(모듈 규격·계약) > 이 문서.
- AI에게는 이 문서 전체를 지침으로 준다.

## 1. AI에게 주는 지침 (만들기 전에)
1. **먼저 사용자에게 묻는다.** 명령어 이름, 바꿀 수 있어야 하는 값(글자 크기·띄우기·레이어·소수점 등), 결과를 어느 레이어에 그릴지, 기존 리습의 동작을 그대로 둘 곳. 모호하면 추측하지 말고 되묻는다.
2. **공용 라이브러리(5장)에서 먼저 찾는다.** 없을 때만 새로 짠다. 새로 짠 도우미가 다른 리습에도 쓸 만하면 모듈 안에 두지 말고 라이브러리에 더한다(라이브러리 → 모듈 순서로 PR).
3. 조정할 값은 코드에 숫자로 박지 않고 선언(3장 `params`)과 변수로 둔다.
4. 다 만든 뒤 7장 점검표를 스스로 확인하고, ClockOut-Lisp의 시험(`dotnet test`)이 통과하게 한다.
5. 남이 만든 리습(원작 코드가 있는 것)은 배포 조건을 확인하기 전에는 공개 묶음에 넣지 않는다. 같은 기능이 필요하면 원작 코드를 보지 않고 새로 짠다(PtM, ClockOut-Lisp `docs/01` 5장).

## 2. 모듈 하나 = 폴더 하나
```
modules/lisp/<모듈id>/
  module.json     선언(3장)
  <id>.lsp        명령 리습. 파일이 크면 역할별로 나눈다(4-3)
  <id>.dcl        대화상자가 있으면
  guide.md        사용법(6장, 필수)
  changes.md      판마다 바뀐 것(최신이 위, 필수)
  README.md       라이브러리 모듈만 필수(5-2)
```
- 폴더 이름 = `id`. id는 영문 소문자로 시작, 영문 소문자·숫자·`-`, 32자 이하(`_` 금지, 칼퇴 저장소 규칙).
- 한 모듈에 리습 파일 여러 개를 묶어도 된다(같이 켜고 끄는 단위가 모듈이다). 서로 따로 켜고 싶으면 모듈을 나눈다.
- 목록을 코드에 박지 않는다. 캐드선수 빌드와 플러그인은 이 폴더들을 읽어 목록을 만든다.

## 3. 선언 `module.json`
```json
{
  "spec": 0,
  "contract_version": 1,
  "id": "pld",
  "kind": "lisp",
  "name": "구간 거리 기입",
  "version": "1.3",
  "author": "주수리",
  "summary": "폴리선 구간마다 거리나 원하는 문구를 적는다.",
  "default": true,
  "memoryMb": 1,
  "startMs": 30,
  "files": ["pld.lsp", "pld.dcl"],
  "load": ["pld.lsp"],
  "commands": [ { "name": "PLD", "text": "폴리선 구간별 거리·문구 기입" } ],
  "requires": ["seonsu-lib"],
  "testedOn": ["R24.0"]
}
```
| 칸 | 필수 | 뜻 |
|---|---|---|
| `spec`·`contract_version` | ○·권장 | 0·1. 칼퇴 `docs/11` |
| `id`·`kind`·`name`·`version` | ○ | `kind`는 `lisp`. `version`은 리습 판(점 숫자, 예 `1.3`) |
| `summary` | ○ | 칼퇴 스위치 옆·팔레트에 보이는 한 문장 |
| `files`·`load` | ○ | 묶음에 넣을 파일 / 도면마다 `(load)`할 파일(`.lsp`·`.dcl`만, `load` ⊂ `files`) |
| `commands` | ○ | 이 모듈이 만드는 명령 전부(`name`=명령어, `text`=한 줄 설명). 팔레트 [실행] 단추와 명령 겹침 검사에 쓴다 |
| `default` | | 칼퇴가 고른 것이 없을 때 켤지. 없으면 켬. 시험용 모듈은 `false` |
| `memoryMb`·`startMs` | | 칼퇴 계기판 어림값. 모르면 넣지 않는다(지어낸 값 금지) |
| `requires` | | 먼저 불러야 할 라이브러리 id(5장). **플러그인 쪽 구현 전**이라 지금은 표시만 한다 |
| `testedOn` | | 시험한 캐드 내부 판(`R24.0` = 2021) |
| `params` | | 조정 값 선언(3-1). **아직 칼퇴·캐드선수가 그리지 않는다**(열린 결정 8장) |

- 화면 모양 칸(`layout`·`tabs`·`ui`·`color` 등)은 넣지 않는다(칼퇴 `docs/11`).
- 판을 바꾸면 리습 안 판 변수(`*<id>-ver*`)와 `version`, `changes.md` 맨 위 항목을 **같이** 올린다. 어긋나면 시험이 실패한다.

### 3-1. 조정 값 `params` (엑셀 추가기능과 같은 모양)
```json
"params": [
  { "key": "textHeight", "label": "글자 크기", "type": "number", "default": 4, "min": 0.5, "max": 50 },
  { "key": "offset", "label": "거리 띄우기", "type": "number", "default": -4 },
  { "key": "decimals", "label": "소수점", "type": "choice", "options": ["0", "1", "2"], "default": "1" },
  { "key": "layer", "label": "기입 레이어", "type": "text", "default": "*_Oper" }
]
```
- `key`·`label`·`type`·`default` 필수, `type`은 `number`·`text`·`bool`·`choice`.
- 리습은 값을 라이브러리의 설정 읽기 함수로만 읽고, 못 읽으면 `default`를 쓴다(5장 `co:opt`).

## 4. 리습 코드 규칙
### 4-1. 파일 머리 주석 (모든 `.lsp`)
```lisp
;;=============================================================================
;;  명령어: PLD (구간 거리 기입)
;;  기능: 폴리선 구간마다 거리 또는 문구를 적는다.
;;  사용법: PLD → 폴리선 고르기 → 옵션 확인 → 엔터
;;  의존: seonsu-lib 0.1 이상(co:guard-begin, co:poly-segments, co:text-make)
;;-----------------------------------------------------------------------------
;;  만든 사람 : 주수리
;;  판        : 1.3 (2026.11)
;;  변경 이력
;;    1.3 (2026.11) - 캐드선수용 사본
;;=============================================================================
(setq *pld-ver* "1.3")
```
### 4-2. 이름
| 무엇 | 모양 | 예 |
|---|---|---|
| 명령 | `c:<명령어>` 대문자 | `c:PLD` |
| 모듈 안 함수 | `<id>:<이름>` | `pld:label-of` |
| 모듈 전역 값 | `*<id>-<이름>*` | `*pld-ver*`, `*pld-last-height*` |
| 라이브러리 함수 | `co:<분야>-<이름>` | `co:sel-get`, `co:poly-segments` |
- 접두어 없는 `defun`(예: `(defun round …)`)은 금지. 다른 리습·회사 리습의 같은 이름을 덮어쓴다.
- 명령어는 다른 모듈과 겹치지 않게 한다(빌드가 모든 `commands`를 모아 겹치면 실패). AutoCAD 기본 명령·별칭(`L`, `CO`, `PL` 등)과도 겹치지 않게 한다.
- 지역 변수는 `defun`의 `/` 뒤에 모두 적는다(전역으로 새지 않게).

### 4-3. 구조 (칼퇴 `docs/02` 3장과 같다)
- 한 파일은 한 가지 책임: 명령 입구(`c:`), 입력 받기, 순수 계산, 그리기를 나눈다. 권장 300줄, 800줄을 넘기지 않는다.
- **순수 계산**(좌표·거리·글자 만들기)은 캐드 개체를 건드리지 않는 함수로 따로 둔다. 시험값을 함께 적는다(`<id>:test` 함수 또는 주석의 입력→결과 예).
- 한 함수는 한 가지 일. 길어지면 이름 붙은 작은 함수로 나눈다.

### 4-4. 안전 (ClockOut-Lisp `docs/02` 3·4장)
- 바꾼 시스템 변수(`OSMODE`, `CMDECHO`, `CLAYER` 등)는 끝날 때와 오류 때(`*error*`) 모두 되돌린다. 라이브러리 `co:guard-begin`/`co:guard-end`를 쓴다.
- 한 번 실행은 되돌리기(UNDO) 한 묶음. `U` 한 번에 전부 취소돼야 한다.
- `*error*`는 `defun` 안 지역으로 만든다(전역 `*error*`를 바꿔 두지 않는다). ESC(`*Cancel*`)는 오류 글 없이 조용히 끝낸다.
- 시작 세트·`acad.lsp`·`acaddoc.lsp`·프로필 레지스트리·`TRUSTEDPATHS`를 고치지 않는다. 불러오기는 캐드선수 플러그인만 한다.
- 다른 리습을 직접 `(load)`하지 않는다. 필요한 것은 `requires`에 적는다.
- 사용 기한 검사·인증 검사는 넣지 않는다(툴용 사본에서 뺀다). 사용법·안내문에 이 얘기를 쓰지 않는다.
- 회사 자료·실제 도면 값(좌표·업체명)을 코드나 예제에 넣지 않는다. 시험은 가짜 자료로.

### 4-5. 글자와 판
- 원본은 **UTF-8**(BOM 없음), 줄바꿈은 원본 그대로. 2020 이하용 CP949 사본은 캐드선수 설치 프로그램이 만든다. 그러니 CP949로 못 바꾸는 글자(이모지·특수 기호)는 쓰지 않는다.
- 지원은 AutoCAD 2015(R20.0) 이상, LT 제외. 판마다 다른 함수(예: 2021 이상만 있는 것)를 쓰면 판을 확인하고 안내한다.

## 5. 공용 라이브러리 (모듈이 할 일만 모듈에)
훈수꾼 `docs/15` 원칙과 같다: **모듈에는 그 기능만의 부분만 두고, 되풀이되는 도우미는 라이브러리에서 받는다.** 라이브러리는 특별한 모듈 하나(`seonsu-lib`, 가칭)다.

### 5-1. 라이브러리 규칙
- 의존은 한쪽뿐: 모듈 → 라이브러리. 라이브러리는 어떤 모듈에도 기대지 않는다.
- 공개 함수는 `co:<분야>-<이름>`. 이미 낸 함수의 이름·인자 순서·돌려주는 모양은 바꾸지 않는다(바꿔야 하면 새 이름으로 더한다). 그래야 라이브러리 판이 올라가도 옛 모듈이 깨지지 않는다.
- 실패해도 오류를 던지지 않고 `nil`을 돌려준다. 이유가 필요하면 `*co-why*`에 글을 남긴다(안내 창을 띄울지는 모듈이 정한다).
- 판은 `*co-lib-ver*`와 라이브러리 `module.json`의 `version`을 같이 올린다. 공개 함수를 더하면 +1(작은 판), 동작을 바꾸면 +1 + 안내.
- 순수 계산 함수에는 시험 함수(`co:test-<분야>`)를 함께 둔다.

### 5-2. **라이브러리 안내 필수** (다른 사람이 쓸 수 있게)
라이브러리를 만들거나 함수를 더하면, 같은 PR에서 라이브러리 폴더의 `README.md`(만드는 사람용 안내, 표 써도 됨)에 아래를 **반드시** 적는다. 이것이 없으면 PR을 합치지 않는다. 같은 내용을 이 저장소 `lisp/README.md`의 라이브러리 줄에서 가리킨다.

1. **한눈에 표**: 분야별로 함수 이름, 인자, 돌려주는 값, 하는 일, 실패하면, 들어온 판.
   ```
   | 함수 | 인자 | 돌려주는 값 | 하는 일 | 실패하면 | 판 |
   | (co:poly-segments ent) | 폴리선 ename | ((시작점 끝점 길이) …) | 구간마다 끝점과 길이 | nil | 0.1 |
   ```
2. **명령어 목록**: 라이브러리가 사용자 명령(`c:`)을 만들면 그 이름과 하는 일. 없으면 "명령 없음"이라고 적는다.
3. **활용법**: 자주 쓰는 조합을 복사해서 쓰는 예 3개 이상(명령 뼈대 포함, 5-3).
4. **모듈에서 부르는 법**: `requires` 적기, 최소 판 확인(`(co:need "0.1")`), 이름 규칙.
5. **고칠 때 주의**: 이름·인자를 바꾸지 말 것, 시험 함수 돌리는 법.
- 함수마다 코드 바로 위에도 한 줄 주석(인자 → 돌려주는 값)을 둔다. `README.md` 표와 같은 말로.
- 모듈의 `guide.md`(사용자용, 칼퇴 안내문 규칙이라 표 금지)와 라이브러리 `README.md`(만드는 사람용)는 읽는 사람이 다르다. 라이브러리 `guide.md`에는 "다른 모듈이 쓰는 공용 부품이라 켜 두세요" 정도만 적는다.

### 5-3. 명령 뼈대 (복사해서 시작)
```lisp
(defun c:XXX ( / *error* st ent segs)
  (setq st (co:guard-begin '("CMDECHO" 0 "OSMODE" 0)))   ; 시스템 변수 저장·UNDO 시작
  (defun *error* (msg) (co:guard-fail st msg "XXX"))      ; 되돌리고, ESC가 아니면 한 줄 안내
  (if (setq ent (co:sel-one "\n폴리선을 고르세요: " '("LWPOLYLINE")))
    (progn
      (setq segs (co:poly-segments ent))
      ;; ... 이 모듈만의 일 ...
    ))
  (co:guard-end st)                                       ; 되돌리기 한 묶음 끝, 변수 복원
  (princ))
```

### 5-4. 처음 넣을 분야 (후보, 리습 후보 목록과 함께 확정)
| 분야 | 예 | 쓰는 곳 |
|---|---|---|
| `guard` | 시스템 변수 저장·복원, UNDO 묶음, 오류 처리 | 모든 명령 |
| `sel` | 하나·여럿 고르기(종류 거르기), 선택 집합 → 목록 | 대부분 |
| `poly` | 정점, 구간 길이, 전체 길이, 닫힘 여부, 점에서 가장 가까운 구간 | 거리 기입, 길이 합계 |
| `text` | 글자 만들기(크기·각도·정렬·스타일), 각도를 읽기 좋게 뒤집기 | 기입 계열 |
| `layer` | 레이어 있으면 쓰고 없으면 만들기, 잠김 확인 | 그리기 계열 |
| `num` | 반올림·자리수·천 단위, 단위 바꾸기 | 기입 계열 |
| `opt` | 설정 값 읽기(`params` default 포함), 도면에 기억 | 옵션 있는 모듈 |
| `file` | CSV 읽기·쓰기(UTF-8/CP949) | 좌표 가져오기·내보내기 |
| `geo` | 경위도 ↔ TM(EPSG 5185~5188, 5173~5177) | 점 관리 |

## 6. 사용자 안내 `guide.md`·`changes.md` (모듈마다 필수)
- 칼퇴 안내문 규칙(칼퇴 `docs/09`)을 따른다: UTF-8, 표·링크·그림·HTML 금지, 글머리 한 단계, 코드 칸(```)은 됨.
- `guide.md`에 적을 것: ① 무엇을 하는지 한두 줄 ② **명령어 전부**(명령 이름과 한 줄 설명) ③ 순서대로 쓰는 법(1, 2, 3) ④ 옵션과 기본값 ⑤ 되돌리기·주의(어느 레이어에 그리는지, 무엇을 바꾸는지).
- `changes.md`: 맨 위가 최신, `## v<판> (날짜)`. 하루에 한 항목.
- 사용 기한, 원작자 코드 여부, AI 활용 같은 말은 사용자 안내에 쓰지 않는다.

## 7. 넣기 전 점검표

## 8. 열린 결정 (사용자 확인 필요)
1. 라이브러리 이름(`seonsu-lib` 가칭)과 함수 접두어 `co:`.
2. 라이브러리를 칼퇴 스위치로 끌 수 있는 모듈로 둘지, 플러그인이 늘 먼저 불러오는 숨은 모듈로 둘지(추천: 늘 먼저 불러옴. 끄면 그것을 쓰는 모듈이 모두 깨지므로).
3. 옵션 값(`params`)을 어디서 바꾸고 어디에 둘지: 칼퇴 설정(`settings.values.json`) / 캐드 안 팔레트 / 각 리습 대화상자. 기억은 도면마다(도면 사전) 또는 PC마다.
