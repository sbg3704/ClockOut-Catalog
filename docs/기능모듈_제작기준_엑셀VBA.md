# 기능 모듈 제작 기준: 엑셀 추가기능(VBA) 편

> 작성일 2026-11-22 · 이 문서는 **엑셀 추가기능 하위 프로그램에 붙는 VBA 기능 모듈**을 만드는 기준이다. 사람이 직접 짜든 AI에게 시키든 같은 기준을 따른다. AI에게는 이 문서 전체를 지침으로 붙여 넣는다.
> 목적: 외부 작성자가 만든 기능 모듈도 칼퇴와 하위 프로그램에 **그대로 호환**되게 하는 것.

## 0. 용어 (2026-11-22 사용자 결정)

| 말 | 뜻 | 예 |
|---|---|---|
| **칼퇴** | 하위 프로그램들을 한곳에서 설치·관리하는 매니저 앱 | |
| **하위 프로그램** | 칼퇴 레일에서 받아 쓰는 한 덩어리의 프로그램 | 엑셀 추가기능, 훈수꾼, 캐드선수 |
| **기능 모듈** | 하위 프로그램에 붙어 일을 하는 낱개 기능 | 엑셀 추가기능에 붙는 `cross-hair`, `value-tools` |

- 이 문서의 주인공은 **엑셀 추가기능이라는 하위 프로그램에 붙는 기능 모듈**이다. 낱개 기능 하나가 `.xlam` 파일 하나로 빌드된다.
- 옛 문서·파일 이름·코드(`addins/` 폴더, `<id>.clockout.json`, `catalog.json`의 `addins`, 칼퇴 화면의 [추가기능] 탭)는 "추가기능"이라는 말을 그대로 쓴다. **거기서 "추가기능 한 개"는 이 문서의 "기능 모듈 한 개"와 같다.** 이름은 바꾸지 않는다(바꾸면 이미 낸 판이 깨진다, 5장).
- 훈수꾼·캐드선수 같은 다른 하위 프로그램의 기능 모듈 기준은 각 프로젝트가 맡아 이 폴더에 추가한다(10장).

## 1. 먼저 알아 둘 것
1. 같은 일을 하는 기능 모듈이 이미 있는지 `catalog.json`과 `addins/`를 본다. 비슷한 게 있으면 새로 만들지 말고 고치자고 제안한다.
2. 공용 부품부터 쓴다(4장). 설정 읽기·선택 범위 검사·안내 창·파일 고르기 같은 것을 다시 짜지 않는다.
3. 직접 다 짜지 않는다. 쓸 만한 공개 VBA가 있으면 활용한다(허용형 라이선스만, 출처·판을 적는다. 8장).
4. 회사 자료·비밀값(토큰, 키, 비밀번호)·개인 정보는 저장소에 올리지 않는다.
5. 클라우드(Linux)에서는 VBA를 컴파일할 수 없다. 컴파일·실행·시험은 Windows Excel에서만 확인되므로, **확인한 범위와 못 한 범위를 PR에 솔직히 적는다.**

## 2. 폴더와 파일

`addins/<id>/` 폴더 하나가 기능 모듈 하나다.

| 파일 | 필수 | 내용 |
|---|---|---|
| `<id>.clockout.json` | ○ | 선언(3장) |
| `*.bas`, `*.cls` | ○ | VBA 소스. **UTF-8**로 저장. 폴더 바로 아래에 둔다(패키지 zip 안에서만 `src/`로 들어간다) |
| `README.md` | ○ | 사람이 읽는 설명(6장) |
| `ThisWorkbook_코드.txt` | 선택 | ThisWorkbook 코드는 `.bas`로 가져올 수 없어 텍스트로 둔다(켤 때·끌 때 처리 등) |

- **id**: 영문 소문자·숫자·하이픈만. 폴더 이름 = 선언의 `id` = 패키지 `<id>.zip` 이름. `_`로 시작하는 폴더(`_common`, `_client`)는 공용 자료 자리라 기능 모듈 id로 쓰지 않는다.
- **한 파일 하나의 책임**: 한 파일은 권장 300줄, 넘기기 전에 나눈다(예: `BookClean.bas`, `BookCleanLinks.bas`, `BookCleanPage.bas`). 수천 줄을 한 파일에 쌓지 않는다.
- **맨 위 한국어 주석**: 기능 / 매크로 이름 / 사용법 / 한계 / 의존. 모양은 `addins/cross-hair/CrossHair.bas` 위쪽을 따른다.
- **Office 개체 없는 계산은 따로**: 시트·도형을 안 쓰는 순수 계산은 별도 모듈에 두고 `Test_`로 시작하는 시험 함수를 함께 둔다(예: `CoFitMath`의 `Test_CoFitMath`).
- 바이너리(`.xlam`, 패키지 zip)는 **저장소에 커밋하지 않는다.** Release 파일로 올린다(7장).

## 3. 선언 파일 `<id>.clockout.json`

```json
{
  "spec": 0,
  "id": "cross-hair",
  "name": "십자 음영",
  "version": "0.1.005",
  "host": "excel",
  "category": "보기·선택",
  "author": "ClockOut",
  "description": "선택한 칸의 행과 열을 연한 색으로 표시합니다.",
  "dependencies": [
    {"id": "clockout-lib", "min_version": "0.1.001", "reason": "설정 읽기와 안내 창에 공용 라이브러리를 씁니다"}
  ],
  "commands": [
    {"id": "toggle", "label": "십자 음영 켜고 끄기", "macro": "CrossHair_Toggle", "tip": "선택한 칸의 행·열을 표시", "key": ""}
  ],
  "params": [
    {"key": "showRow", "label": "행(가로줄) 음영", "type": "bool", "default": true}
  ]
}
```

### 3-1. 최상위 칸
| 칸 | 필수 | 설명 |
|---|---|---|
| `spec` | ○ | 지금은 0만. 되돌릴 수 없는 규격 변경 때만 올라간다(5장) |
| `id`, `name`, `version`, `host` | ○ | `host`는 지금 `excel`. `version`은 `X.Y.Z`(앞의 `v`는 무시) |
| `description` | 권장 | 하는 일 설명. 목록의 안내 말풍선에 보인다 |
| `author`, `site` | 선택 | `site`는 `https://`로 시작하는 주소만 허용 |
| `category` | 선택 | 찾기 화면의 구역(값 정리 / 표·범위 / 시트·문서 / 보기·선택 / 사진·도형). 없으면 "기타" |
| `dependencies` | 선택 | 필요한 라이브러리(4장) |
| `commands` | 선택 | 사용자에게 보일 명령(3-2). 리본·단축키 표·충돌 검사가 여기서 나온다 |
| `params` | 선택 | 설정창으로 그릴 조정 값(3-3) |
| `type` | 선택 | 라이브러리면 `"library"`(`category`도 `"라이브러리"`) |

### 3-2. `commands` (배열)
| 칸 | 필수 | 설명 |
|---|---|---|
| `id` | ○ | 이 기능 모듈 안에서 유일한 영문·숫자·밑줄. 단축키 설정 키에 쓰인다 |
| `label` | ○ | 사람에게 보이는 이름 |
| `macro` | ○ | 부를 **공개 Sub 이름**(모듈 이름 없이) |
| `group`, `icon`, `tip`, `key` | 선택 | 리본 묶음 / Office 내장 아이콘 이름(imageMso) / 한 줄 설명 / 기본 단축키 |

- 기본 단축키(`key`)는 **비워 두는 것이 기본**이다. 정한다면 `Application.OnKey` 형식(`^`=Ctrl, `+`=Shift, `%`=Alt, 예 `^+H`). 엑셀 기본 키(Ctrl+C/V/X/Z/Y/S/A/F/H 등)나 글자 하나만 누르는 키는 위험으로 경고된다.
- 사용자가 바꾼 키는 칼퇴가 `key.<명령id>`로 설정에 저장한다. 기능 모듈은 시작할 때 이 값을 읽어 등록한다(공용 라이브러리 `CoKey_*`). 바꾼 키는 엑셀을 다시 켜야 적용된다.
- 필수 칸이 없거나 id가 틀리거나 중복이면 그 명령만 건너뛰고 경고한다. 사용자 실수로 PC의 엑셀 기본 동작을 가로채지 않도록 이 검사를 믿고 선언한다.

### 3-3. `params` (설정 값)
- 칸: `key`, `label`, `type`, `default`는 필수. 선택: `unit`, `min`, `max`, `options`, `help`(툴팁).
- `type`은 `number`(단위·최소·최대 검사), `bool`(체크박스), `choice`(`options` 목록), `text`. 모르는 종류는 글자 입력칸으로 보인다.
- **조정할 수 있는 값은 코드에 숫자로 박지 않는다.** 여백·크기·색·범위처럼 사용자가 만지고 싶을 값은 `params`로 선언하고 코드에서 읽는다. 읽기에 실패하면 선언의 `default`를 쓴다(코드의 기본값과 JSON의 `default`·`min`·`max`를 같게 맞춘다).
- 값은 사용자 PC의 `%APPDATA%\ClockOut\settings\<id>.json`에 저장된다. **추가기능 파일 안에는 사용자 값을 저장하지 않는다**(저장하면 SHA-256 검증과 업데이트 후 설정 유지가 깨진다).
- 같은 효과를 내는 대체 방식으로 코드 맨 위 주석(`'@clockout id=… name=… host=excel`, `'@param …`)도 읽지만, 오타에 약하니 JSON을 쓴다.

## 4. 공용 라이브러리와 종속성

- 공용 VBA 부품은 `addins/_common/`(`clockout-lib`)에 있다. 기능 모듈은 **여기서 먼저 찾아 쓴다.** **함수 목록·인자·동작·부르는 법·예제는 `docs/공용라이브러리_함수설명서.md`**(소스 쪽 설명은 `addins/_common/README.md`).
- 방향은 한쪽뿐이다: **기능 모듈 → 공용 라이브러리.** 라이브러리가 기능 모듈을 참조하지 않고, 기능 모듈끼리도 서로의 함수에 기대지 않는다.
- 라이브러리에 없는 도우미가 필요하면 기능 모듈 안에 비슷한 함수를 새로 만들지 말고 **라이브러리에 더해 달라고 제안**한다(이슈 또는 PR).
- 쓰는 라이브러리는 선언의 `dependencies`에 정확히 적는다.
  ```json
  "dependencies": [{"id": "clockout-lib", "min_version": "0.1.001", "reason": "…", "bundled": false}]
  ```
  `id`(영문·숫자·하이픈·점), `min_version`(`X.Y.Z`, 없으면 판 제한 없음), `reason`(안내 화면에 보일 글), `bundled`(기본 `false`; `true`면 이 `.xlam`에 라이브러리가 함께 컴파일돼 있다는 뜻이라 설치 요구를 하지 않는다). 자기 자신 참조·같은 id 중복·서로 필요로 하는 순환은 거부된다. 칼퇴는 부족한 라이브러리를 안내만 하고 자동 설치하지 않는다.
- 독립 라이브러리를 쓰는 기능 모듈은 `CoLibClient.bas`(빌드가 자동으로 넣는다)로 라이브러리 개체를 받는다.
  ```vb
  Dim coApi As Object
  Set coApi = CoLibClient_Api("0.1.001", "십자 음영")   ' 없거나 판이 낮으면 안내 후 Nothing
  If coApi Is Nothing Then Exit Sub
  coApi.CoGuard_Notice "안내 글"
  ```
  최소 판은 선언의 `min_version`과 같게 적는다. 이벤트처럼 자주 불리는 곳은 `quiet:=True`. 시작 때 라이브러리를 부르면 아직 안 켜졌을 수 있으니 `Workbook_Open`에서 `Application.OnTime`으로 조금 뒤에 실행한다.
- 외부 공개 VBA(JSON, 사전, 정규식 등)는 소스를 복사하지 말고 `clockout-vendor-*` 라이브러리 묶음을 쓴다(`addins/_client/README.md`).

## 5. 하위 호환 규칙 (가장 중요)

칼퇴 화면이 바뀌거나 칼퇴·라이브러리 판이 올라가도 **이미 낸 기능 모듈은 고치지 않고 계속 돌아야** 한다. 모듈화하는 이유가 이것이다.

1. **선언은 내용만 낸다.** 이름·설명·명령·설정 값만 적고, 화면 모양(탭 순서·색·배치·아이콘 위치)은 넣지 않는다. 화면은 칼퇴가 공통 틀로 그린다.
2. **선언에는 이 문서의 칸만 쓴다.** 모르는 칸은 칼퇴가 무시한다(읽기를 거부하지 않는다). 거꾸로, 칼퇴에 알리고 싶은 새 기능은 선언 칸을 지어내지 말고 칼퇴 쪽에 요청한다.
3. **새 칸은 늘 선택 항목이다.** 필수 칸은 늘리지 않는다. 칸이 없는 선언은 계속 유효하다.
4. **되돌릴 수 없는 변경만 `spec`을 올린다.** `spec`이 칼퇴가 아는 값보다 높으면 "더 새 칼퇴가 필요"로 설치가 거부된다. 일반 추가는 올리지 않는다.
5. **이미 쓰는 공개 함수의 이름·인자 순서는 바꾸지 않는다.** 다른 기능 모듈이 깨진다. 바꿔야 하면 새 이름으로 더한다. 공개 매크로(`commands`의 `macro`)와 `id`도 낸 뒤에는 바꾸지 않는다(단축키·설정 저장이 `id`에 묶여 있다).
6. **지우거나 뜻을 바꾸지 않고 더하기만 한다.** 설정 키 이름과 기본값의 뜻도 같다. 바꿔야 하면 새 키를 쓰고 옛 키를 읽어 넘겨받는다.
7. 판은 `X.Y.Z`. 고침은 +1, 새 기능 덩어리는 +10, 구조 변경은 +100 정도의 무게로 올린다. 같은 id·판을 다시 올리면 파일 해시가 달라지므로 **고칠 일은 판을 올려 새 Release로** 낸다.

## 6. VBA 코딩 규칙

**꼭 지킬 것**
- 매크로는 공용 도우미로 시작·끝낸다. 시작에 `CoGuard_Begin`(화면 갱신·이벤트·계산·상태 표시줄 저장), 끝과 오류 처리에 `CoGuard_End`로 복원한다. 오류 시에도 반드시 복원된다.
- 선택 범위·활성 시트는 `CoRange_GetSelection` 등 검사 함수로 확인한 뒤 쓴다(병합·보호·잠긴 칸·숨김·행 전체 선택 등).
- 오류는 삼키지 않는다. 화면에는 알아듣기 쉬운 안내를 보이고, 빈 `On Error Resume Next`를 길게 쓰지 않는다. 오류 글은 `Err`가 지워지기 전에 맨 먼저 잡는다(`CoGuard_ErrText`).
- 실패해도 오류를 밖으로 던지지 않고 `False`·`""`·기본값을 돌려주는 함수로 만든다. 검사 함수는 안내 창을 직접 띄우지 않고 이유 글을 돌려주고, 띄울지는 매크로가 정한다.
- **밖에서 온 값은 믿지 않는다.** 설정 값·고른 파일·다른 문서의 내용은 경계에서 검사하고 빨리 실패한다.
- **되돌릴 수 없는 일은 먼저 확인받는다.** 지우기·덮어쓰기·정리는 대상을 목록으로 보여 주고 확인을 받은 뒤 한다.
- 인터넷이 없어도 돌아야 한다(오프라인 안전). 외부로 데이터를 보내는 기능은 만들지 않는다.
- 이름: 소스 파일 `Option Explicit`, 공개 Sub은 `<모듈>_<동작>`(예 `CrossHair_Toggle`), 공용 라이브러리는 `Co<분야>_<동사·명사>`. 공개 상수는 `CO_` 대문자.
- **지역 변수·인자 이름**으로 `name`·`out`·`scale`·`inStr`·`base`·`w`·`h` 처럼 VBA 예약어나 내장 함수와 겹칠 낱말을 쓰지 않는다(한글판 Excel에서 컴파일 오류가 난다). `fileName`·`outText`·`fitScale`처럼 붙여 쓴다.
- 소스에 이모지 같은 **CP949로 쓸 수 없는 글자**를 넣지 않는다(한글판 VBA 편집기가 읽는 인코딩이 CP949라 빌드가 멈춘다).

**뼈대 (복사해서 시작, 독립 라이브러리 방식)**
```vb
Private Const ADDIN_ID As String = "my-addin"     ' 선언의 id와 같게
Private Const ADDIN_NAME As String = "내 기능"
Private Const MIN_LIB As String = "0.1.001"        ' 선언 dependencies의 min_version과 같게

Public Sub MyAddin_Run()
    Dim lib As Object, tok As Long, msg As String, why As String
    Dim ws As Worksheet, rng As Range, margin As Double

    Set lib = CoLibClient_Api(MIN_LIB, ADDIN_NAME): If lib Is Nothing Then Exit Sub
    If Not lib.CoRange_GetSelection(ws, rng, why) Then lib.CoGuard_Notice why: Exit Sub
    If Not lib.CoRange_CanEdit(rng) Then lib.CoGuard_Notice "보호된 셀이 있습니다.": Exit Sub
    margin = lib.CoSetting_Number(ADDIN_ID, "margin", 1#, 0, 20)   ' 선언의 default·min·max와 같게

    tok = lib.CoGuard_Begin()
    On Error GoTo EH
    ' ... 작업 ...
    lib.CoGuard_End tok
    Exit Sub
EH:
    msg = lib.CoGuard_ErrText("작업 중")   ' 맨 먼저: 다음 줄들이 Err를 지운다
    lib.CoGuard_End tok
    lib.CoGuard_Notice msg
End Sub
```
(`CoLibClient_Api`는 빌드가 `dependencies`를 보고 자동으로 넣는 연결부다. 선언에 `"bundled": true`를 적고 라이브러리 `.bas`를 함께 컴파일하는 예전 방식에서는 `lib.` 없이 `CoRange_GetSelection(...)`처럼 부르고 `CoGuard_Begin`은 `CoAppState`를 돌려준다.) **어떤 함수가 있고 어떻게 부르는지는 `공용라이브러리_함수설명서.md`에 함수마다 적혀 있다.**

## 7. README와 패키지

**기능 모듈 README.md에 적을 것**: 하는 일(한두 문단) / 켜고 쓰는 법(매크로·리본·단축키) / 설정(칼퇴 설정창에서 바꾸는 값) / 필요한 것(라이브러리와 최소 판) / 원리 / **알아둘 점·한계** / 확인한 범위(시험한 엑셀 판과 못 시험한 것). 화면에 "무료 운영"·"개인 프로젝트" 같은 영구 약속 문구는 쓰지 않는다.

**패키지 zip** (빌드 스크립트가 만든다. 직접 만든다면 아래를 지킨다)
- 이름 `<id>.zip`. 맨 위(하위 폴더 없이)에 `.xlam`(또는 `.xla`)이 **정확히 하나**. 0개나 2개 이상이면 설치하지 않는다.
- 같은 이름의 `<id>.clockout.json`을 맨 위에 둔다. 선택으로 `README.md`, `src/` 아래 `.bas`·`.cls`(참고용, 설치되지 않음).
- `.exe`·`.dll`·`.bat`·`.cmd`·`.vbs`·`.ps1` 같은 **실행 파일이 하나라도 있으면 설치를 거부**한다. 절대 경로·`..`·`\`·`:`가 든 경로도 거부한다.

## 8. 외부 코드를 쓸 때
- **허용형 라이선스(MIT 등)만.** 원본은 고치지 않고 `vendor/vba/`에 두며, 출처·커밋·라이선스를 `vendor/vba/SOURCES.md`에 적는다. 라이선스 전문은 배포 zip에 함께 들어가게 한다.
- 원작을 개조·재배포할 수 없는 코드는 가져오지 않는다. 같은 일을 하는 코드를 원작을 보지 않고 새로 짜야 한다.
- 만들거나 가져온 코드 소스에는 만든 사람이 적히게 한다(`author`).

## 9. 올리는 방법과 검수

1. 이 저장소를 포크하거나 브랜치를 만들어 `addins/<id>/`를 추가하고 **PR**을 연다. 브랜치 이름은 `claude/<범위>-<세부>-<일번호>-<슬러그>` 방식을 권한다(범위 코드는 저장소 소유자에게 묻는다). PR 본문에는 아래를 적는다.
   - ① 무엇을 왜 ② 끝난 것 ③ 남은 일과 다음 할 일 ④ **확인한 범위와 못 한 것** ⑤ 관련 결정(이 문서의 장 번호) ⑥ 먼저 읽을 파일 3개 이내.
2. 빌드는 Windows Excel이 있는 PC에서 `tools/build_addin.ps1 -Addin <id> -RunTests`(사용법: `tools/build_addin.md`). 컴파일 오류가 없고 시험이 통과해야 한다.
3. **검수는 운영자가 한다.** 운영자가 소스를 읽고 빌드·시험을 확인한 것만 올라간다.
4. 배포는 운영자가 한다. `tools/publish_addin.ps1`이 빌드 → zip의 SHA-256·크기 계산 → GitHub Release(태그 `<id>-<판>`) 올리기 → `catalog.json` 항목 등록을 한다. **Release를 먼저 올리고, 그 뒤에 `catalog.json` PR을 머지**한다(카탈로그가 먼저 나가면 받을 파일이 없다).
5. 칼퇴는 `catalog.json`을 받아 읽는다. 받은 파일의 SHA-256이 `sha256`과 다르면 파일을 지우고 설치하지 않는다. 받아도 되는 주소는 이 저장소의 Release와 raw 파일뿐이다.

`catalog.json` 항목(추가기능 구역)은 이렇게 생겼다. 필수는 `id`·`name`·`version`·`url`·`sha256`, 선택은 `description`·`author`·`site`·`category`·`size`(100MB 이하)·`dependencies`.
```json
{
  "id": "cross-hair", "name": "십자 음영", "version": "0.1.005",
  "author": "ClockOut", "host": "excel", "category": "보기·선택",
  "description": "…",
  "url": "https://github.com/sbg3704/ClockOut-Catalog/releases/download/cross-hair-0.1.005/cross-hair.zip",
  "sha256": "<zip의 SHA-256 소문자 16진수 64자>", "size": 123456
}
```
- 라이브러리(`.xlam`)는 같은 `addins`에 `category: "라이브러리"`로 올린다(`libraries`는 소스 묶음 zip 전용).
- 항목 하나가 틀려도 나머지는 쓰이고 틀린 항목만 건너뛴다. `spec`을 모르는 판이거나 JSON이 깨지면 카탈로그 전체를 쓰지 않는다.

## 10. 다른 하위 프로그램의 기능 모듈 기준 (자리)

훈수꾼·캐드선수처럼 따로 도는 하위 프로그램은 기능 모듈을 만드는 방식이 다르다(선언·화면·설치가 다름). 각 프로젝트가 **자기 기준을 이 `docs/` 폴더에 별도 문서로** 쓴다. 공통 계약과 써야 할 항목은 `하위프로그램_기능모듈_공통계약.md`. 이름은 `기능모듈_제작기준_<하위프로그램>.md`로 맞춘다.

| 하위 프로그램 | 기준 문서 | 상태 |
|---|---|---|
| 엑셀 추가기능(VBA) | `기능모듈_제작기준_엑셀VBA.md` (이 문서) | 작성됨 |
| 훈수꾼 | `기능모듈_제작기준_훈수꾼.md` | 미작성 |
| 캐드선수 | `기능모듈_제작기준_캐드선수.md` | 미작성 |

공통으로 지킬 원칙은 5장과 같다: 선언은 내용만 내고, 칼퇴와는 정해진 명령으로만 이어지며, 새 칸은 선택 항목이고, 모르는 칸은 무시하며, 낸 판을 깨지 않는다.
