# 공용 라이브러리 함수 설명서: 훈수꾼 편

> 작성일 2026-11-22 · 훈수꾼 0.0.267, 다리(`clockout-hunsu`) 0.0.021 기준. 내용은 훈수꾼 소스의 **실제 코드·머리 주석**(선언 읽기, 글 틀·조건, 부품, 다리 VBA 조회·명령)과 기본 기능 모듈 27개의 선언에서 옮겼다. 소스와 다르면 소스가 이긴다. 라이브러리를 고치면 이 문서도 **같은 PR에서** 고친다(공통 계약 9장 5-1).
> 읽는 사람: 훈수꾼 기능 모듈을 만드는 사람(AI 포함). 제작 기준 전체는 `기능모듈_제작기준_훈수꾼.md`. 엑셀 추가기능(VBA) 편 함수 설명서는 `공용라이브러리_함수설명서.md`(별개).
> **확인 범위**: 소스를 읽어 정리했다. 클라우드에서는 훈수꾼 화면도 엑셀도 돌려 볼 수 없어, 각 조회의 응답 예는 소스 머리 주석의 예이고 이 문서를 쓰며 엑셀에서 다시 실행하지는 않았다. 소스 주석의 시험 결과(Windows 엑셀)를 그대로 믿지 말고 새 기능 모듈을 만들 때 직접 확인한다.

## 1. 왜 공용인가, 어떤 층이 있는가
기능 모듈이 창 만들기·따라다니기·단축키·옵션 창·저장·엑셀 읽기를 저마다 짜면 같은 버그가 기능 모듈 수만큼 생긴다. 훈수꾼에서는 **기능 모듈이 코드 없이 선언만** 하고 나머지는 모두 공용이 한다. 규칙은 둘이다.
1. **새로 만들기 전에 이 문서에서 먼저 찾는다.**
2. 없으면 기능 모듈 안에서 우회하지 말고 **공용에 칸을 더해 달라고 요청**한다(제작 기준 5장).

| 층 | 무엇 | 기능 모듈이 쓰는 법 | 이 문서 |
|---|---|---|---|
| ① 선언 문법 | 글 틀·조건·데이터 경로·명령 인자 | 선언의 글 안에 쓴다 | 2장 |
| ② 화면 부품 | 큰 숫자·목록·단추·막대 …, 셀 위 표시층, 손잡이 | `view.json`에 이름으로 고른다 | 3장 |
| ③ 틀의 공용 선언 칸 | 따라다니는 글(`hud`), 옵션(`quick`), 단축키, 자리 | 선언 칸으로 쓴다 | 4장 |
| ④ 다리 조회·명령 | 엑셀에서 값을 읽고 이동·실험 쓰기 | `data.topic`·`commands`로 이름을 쓴다 | 5·6장 |
| ⑤ 다리 진입점 | 훈수꾼이 `Application.Run`으로 부르는 VBA 3개 | 기능 모듈은 직접 부르지 않는다 | 7장 |

기능 모듈이 직접 부르는 **함수는 없다.** "함수"는 선언에 적는 이름(글 틀 형식, 조건 연산자, 부품, 조회, 명령)이다. 아래 각 항목에 **인자(칸)·반환(보이는 결과)·동작·부르는 법·짧은 예제**를 적었다. 구현 이름(`Template`, `Condition` 등)은 "어디가 하는 일인지"를 알리려는 것이며 기능 모듈이 이름으로 부르지 않는다.

## 2. 선언 문법

### 2-1. 글 틀 `{경로:형식}` (`Template.Render`)
- 선언의 글 칸(부품 `text`·`label`·`value`·`badge`, `hud.parts[].text`, `arg.*` …)에서 `{...}`를 **실제 값**으로 바꾼다. `{`가 닫히지 않으면 그대로 둔다.
- **인자**: 경로(2-3), 형식(선택). **반환**: 글.

| 형식 | 값이 숫자일 때 | 예 (값 1234.5) |
|---|---|---|
| (없음) | 그대로(소수점은 점) | `{a.v}` → `1234.5` |
| `n` | 천 단위 구분, 소수 둘째까지 | `{a.v:n}` → `1,234.5` |
| `n0` | 천 단위 구분, 정수 | `{a.v:n0}` → `1,235` |
| `p` | 백분율 | `{a.v:p}` → `123450%` (값 0.25 → `25%`) |

- 값이 글이면 그대로, 참이면 `예`, 거짓이면 `아니오`, 값이 없으면(경로 없음·null) `-`. 배열·객체는 JSON 글 그대로. **계산은 하지 않는다**(더하기·빼기 같은 식은 쓸 수 없다).
- 예: `"text": "합계 {selection.summary.sum:n} · {selection.summary.nonEmpty:n0}개"` → `합계 1,234.5 · 12개`.

### 2-2. 조건 한 줄 (`Condition.Evaluate`)
- `showWhen`·`hideWhen`·`activeWhen`·`hud.when`·`hud.parts[].when`에 쓴다. **인자**: 조건 글. **반환**: 참/거짓.
- 문법: `<경로> <연산자> <값>`. 연산자 `==` `!=` `>=` `<=` `>` `<`(이 순서로 찾는다). 값은 숫자·`"글자"`·`true`·`false`·`null`.
- 경로만 쓰면 "값이 있고 0·빈 글·`false`가 아니면" 참. 값이 없는 경로 비교는 `== null`이 참, 숫자 비교는 `!=`만 참.
- **받지 않는 것**: 괄호, `&&`, `||`, 함수, 사칙연산. 이런 글은 거짓으로 본다(기능 모듈이 코드를 돌리지 못하게). 둘 이상의 조건이 필요하면 부품을 나눠 각각 `showWhen`을 둔다.
- 예: `"showWhen": "errors.count > 0"`, `"when": "selection.summary.sum != null"`, `"activeWhen": "item.active == true"`.

### 2-3. 데이터 경로 (`DataScope`)
- 기능 모듈이 `data`로 구독한 **주제(조회 이름) 한 개 = 응답 JSON의 `data` 객체 한 개**다. 경로는 `주제이름.칸.칸`이다. 주제 이름에 점이 들어 있어도(`selection.summary`) **가장 긴 주제 이름이 앞부분과 맞는 것**을 고른 뒤 나머지를 `.`로 따라간다.
- 예: 구독 `selection.summary`의 응답이 `{"count":3,"sum":12.5}`이면 `selection.summary.sum` = 12.5. 배열 안 항목은 경로로 부를 수 없고(`list`·`bar` 같은 부품이 줄마다 돈다) 줄 안에서는 `{item.칸}`을 쓴다.
- 구독하지 않은 주제의 경로는 값이 없다(`-`/거짓). **응답에 없는 칸도 예외 없이 `-`** 이다.
- 앱이 채우는 주제는 이름이 `app.`으로 시작한다(예: `app.history`). 다리에 묻지 않는다.

### 2-4. 명령 인자 (`CommandArgs.Build`)
- 단추·목록 줄이 `command`와 함께 보낼 인자는 `"arg.<이름>": "글 틀"`로 적는다. 틀이 모든 `arg.*`를 글 틀로 채워 **글자 값만 가진 JSON 객체 하나**로 묶는다(`{"addr":"B2","sheet":"매출"}`). 값은 늘 글자이고 JSON 규칙대로 이스케이프되므로 선언이 JSON 문장을 직접 만들 수 없다.
- 목록 줄에서는 `{item.칸}`, 단추에서는 구독 경로를 쓴다.
- 예: `{"type":"list","items":"errors.items","text":"{item.addr}","command":"goto","arg.addr":"{item.addr}","arg.sheet":"{item.sheet}"}`.
- **명령 이름이 이 기능 모듈의 `commands` 허용 목록에 없으면 보내지 않는다.**

## 3. 화면 부품

### 3-1. `view.json` 최상위
| 칸 | 설명 |
|---|---|
| `tab` | 접힌 손잡이 `{title, badge, tone}`. 모두 글 틀. `title` 기본은 기능 모듈 이름, `tone` 기본 `info` |
| `chip` | 상시 띠 조각(`{...}` 한 개, 글 틀) |
| `panel` | 부품 배열(위에서 아래로) |
| `marks` | 셀 위 표시층 배열(3-4) |

- 모르는 부품 `type`·톤은 **그 줄만 건너뛰고** 기록한다(`view_warn`). JSON이 깨지면 `view_failed`로 그 기능 모듈이 건너뛰어진다.
- **모든 부품 공통 칸**: `type`(필수), `showWhen`(조건이 참일 때만 보임), `hideWhen`(참이면 숨김), `tone`(`info`·`good`·`warn`·`bad`·`muted`, 글 틀 가능).
- 톤은 색 이름이 아니라 **뜻**이다(좋음/주의/나쁨/흐림/정보). 실제 색은 사용자가 고른 테마·룩이 정한다. 색 숫자·글꼴은 선언에 쓰지 않는다.

### 3-2. 부품 9종 (그려진다)
| `type` | 칸 | 하는 일 · 예 |
|---|---|---|
| `stat` | `value`, `label`, `tone` | 큰 숫자 하나와 작은 설명. `{"type":"stat","value":"{errors.count:n0}","label":"오류 셀 · {errors.sheet}","tone":"bad"}` |
| `text` | `text`, `tone` | 한두 줄 글. 길면 말줄임 대신 줄바꿈 |
| `badge` | `text`, `tone`(기본 `info`) | 작은 알약 모양 글 |
| `divider` | (없음) | 가로 구분선 |
| `list` | `items`(배열 경로), `text`, `sub`, `tone`, `command`, `arg.*`, `max`, `emptyText`, `activeWhen` | 배열을 줄로 그리고 줄을 누르면 `command`를 보낸다. 줄 안에서 `{item.칸}`. 줄 수 = `min(max, 설정 listMaxRows)`, 넘으면 "외 N개" 표시. 비었으면 `emptyText`(기본 "표시할 항목이 없습니다."). `activeWhen`이 참인 줄은 강조 |
| `button` | `text`, `command`, `arg.*` | 단추 하나. 누르면 명령 전송 |
| `bar` | `items`+`label`+`value`(배열), 또는 `value`+`total`(한 줄), `tone`, `max` | 막대. 숫자가 아니면 `-`와 빈 막대. 예외를 내지 않는다 |
| `spark` | `values`(배열 경로), `field`(객체 배열일 때), `label`, `format`(`n0` 등), `tone` | 작은 추세선 |
| `progress` | `label`, `value`, `total`(없으면 `value`를 0~1 비율로), `tone`(기본 `good`) | 진행 막대 |

### 3-3. 이름만 받는 부품 (아직 그려지지 않음)
`toggle`·`input`·`flow`·`tabs`는 선언을 읽지만 **"'<이름>' 부품은 준비 중"** 자리표시로 그려진다. 쓰지 않는다. 필요하면 공용에 구현을 요청한다.

### 3-4. 셀 위 표시층 `marks[]`
```json
"marks": [
  {"items": "mark.errors", "tone": "bad",  "style": "outline"},
  {"items": "mark.pre",    "tone": "info", "style": "fill"},
  {"items": "mark.dep",    "tone": "good", "style": "underline", "enabledKey": "someToggle"}
]
```
- 선언 `data`에 `mark` 조회를 구독해야 한다(5장 `mark`). `items`는 칸 자리(화면 픽셀 `x,y,w,h` 배열)의 데이터 경로.
- `style`: `outline`(테두리) · `fill`(옅은 칠) · `underline`(밑줄) · `pencil`(손으로 그린 색연필 수식 흐름). 모르는 모양은 그 줄을 건너뛴다. `tone`은 위 톤 이름이고 기본 `info`.
- `enabledKey`(선택): 이 그림을 켜고 끄는 설정 키(참일 때만 그림, "일하는 중" 점도 같이 끔).
- `pencil`은 `role`이 필요하다: `active`(고른 칸을 두름) · `pre`(쓰는 칸, 화살표가 고른 칸으로) · `dep`(쓰이는 칸) · `pre2`/`dep2`(한 단계 더 앞/뒤) · `crossPre`/`crossDep`(다른 시트에서 오는/가는 칸, `flow.graph` 항목) · `tabs`(시트 탭 이름 순서, `sheets` 항목). 칸 자리에 `addr`가 있어야 한다. 본보기 `hunsu-pencilflow`.
- 새 그리기 방식은 틀에 `IMarkStyle` 하나를 더하는 일이다(기능 모듈이 할 수 없음). 필요하면 요청한다.

## 4. 틀의 공용 선언 칸

### 4-1. 따라다니는 글 `hud` (`HudSpec.Render`)
선언 칸은 제작 기준 3-6. 동작:
1. `when`이 있고 거짓이면 글이 없다(안 보임).
2. `parts[]` 중 `when`이 없거나 참인 것의 글 틀을 채운다.
3. 빈 글을 빼고 `join`(기본 빈 글)으로 잇는다. 하나도 없으면 안 보인다.
- 붙는 곳: `anchor` `cursor`(범위를 끄는 동안 커서 옆) · `cell`(고른 칸 옆 계속). `anchorKey`가 가리키는 설정이 `cursor`/`cell`이면 그 값이 우선, 모르는 값이면 선언의 `anchor`. 고른 칸 옆 HUD가 하나라도 켜져 있으면 틀이 `mark` 조회를 자동으로 더 받는다.
- 창 크기: `size {"width": 120~800, "height": 60~800}`(범위 밖이면 선언 오류).

### 4-2. 전역 단축키 `quick[].hotkey` (`HotkeyChord.TryParse`)
- **인자**: 글(예 `"Ctrl+Alt+D"`). **반환**: 수식키+가상 키 코드와 보기 좋게 다듬은 글. 못 읽으면 선언 오류(`quick … hotkey`).
- 규칙: `Ctrl` 또는 `Alt` 중 **하나 이상 필수**(수식키 없이 글자만 가로채면 타자를 막는다). `Shift`는 더해도 된다. 키는 하나, **A~Z·0~9·F1~F12**만. 훈수꾼 자체 단축키(`Ctrl+Alt+H` 부르기, `Ctrl+Alt+Shift+H` 전부 숨기기)와 겹치면 거절. 대소문자·순서 무관, `+`로 잇는다.
- 같은 키를 두 기능 모듈이 선언하면 앞선 기능 모듈만 쓴다. 엑셀이 앞에 있을 때만 등록된다. 다른 프로그램이 이미 쓰는 키는 등록에 실패하고 기록에 남는다.
- 예: `{"kind":"toggle","key":"pencilDraw","label":"그리기 켜기 (Ctrl+Alt+D)","hotkey":"Ctrl+Alt+D"}`.

### 4-3. 옵션 `quick[]` (`QuickSchema`)
- 읽기(`Read`): 잘못된 항목은 오류로 모으고 그 항목만 건너뛴다. `label` 필수. `menu`는 `items` 필요(하위도 같은 규칙). `toggle`·`choice`는 `key` 필수. `choice`는 `options` 2개 이상(`{value,label}`). 모르는 `kind`·모르는 `apply` 값은 오류.
- 배치(`Arrange`): `order`(작을수록 위, 없으면 선언 순서) 다음 선언 순서로 늘어놓고 같은 `group`끼리 모은다. 묶음 순서는 그 묶음에서 가장 앞선 항목을 따른다. `group`이 비면 제목 없음.
- 값: 현재 값은 설정 JSON에서 키로 읽은 글(소문자). `choice`의 `value`가 숫자 글이면 숫자로, `true`/`false`면 불리언으로, 아니면 글로 저장한다. 그림은 훈수꾼이 한다: 우클릭 메뉴(묶음 제목·구분선·하위 메뉴·체크)와 설정 창 [옵션] 쪽이 **같은 선언**을 읽는다. 메뉴 맨 아래에는 늘 열기·닫기, 핀 창으로 떼기, 반대쪽 도크, 자세히 설정…이 있다.

### 4-4. 기능 모듈이 쓸 수 있는 설정 키
`quick[].key`·`hud.enabledKey`·`hud.anchorKey`·`marks[].enabledKey`는 훈수꾼 설정(`settings.json`)의 키다. **기능 모듈은 새 키를 만들 수 없고** 이미 있는 키만 쓴다. 기본 기능 모듈이 쓰는 키:

| 키 | 값 | 기본 | 쓰는 곳 |
|---|---|---|---|
| `listMaxRows` | 숫자(보통 20·50·100·200) | 50 | 목록 부품의 줄 수 상한(`list`가 `min(max, listMaxRows)`). 목록 기능 모듈 14개가 `quick` choice로 선언 |
| `cursorHud` | 참/거짓 | 참 | 끄는 동안 커서 옆 합계 켜고 끄기(`hunsu-selection`) |
| `hudAnchor` | `cursor`·`cell` | `cursor` | 합계 HUD가 붙는 곳 |
| `pencilDraw` | 참/거짓 | 참 | 색연필 수식 흐름 그리기 켜고 끄기(Ctrl+Alt+D) |
| `pencilLook` | `pencil`·`marker`·`ink` | `pencil` | 그림 모양 |

그 밖의 설정(독 모양·테마·불투명도·사이드바 …)은 **사용자 몫이고 틀의 일**이라 기능 모듈이 건드리지 않는다. 새 설정 키가 필요하면 훈수꾼이 설정 속성(범위 검사 포함)을 더해야 한다.

### 4-5. 자리 `place` (`Places`)
| 코드 | 쓰는 모양 | 뜻 |
|---|---|---|
| `edge-left`, `edge-right` | tab, panel | 가장자리 도크 |
| `mark` | mark | 셀 위 표시층 |
| `strip` | chip | 상시 띠 |
| `summon`, `pin`, `second` | window, panel | 호출층·핀 창·보조 모니터(`window`가 없으면 `panel`을 창에 넣음) |

`place`에 놓을 모양이 `shapes`에 하나라도 있어야 한다. 기본 27개는 모두 `edge-left`다.

### 4-6. 켜고 끄기와 읽는 곳 (`ModuleGate`, `ModuleSources`)
- `ModuleGate`: `CLOCKOUT_MODULES_FILE`(`{"spec":0,"enabled":[...]}`)에서 켜진 기능 모듈 id를 읽는다. `enabled`에 없는 기능 모듈은 선언도 읽지 않는다. 읽을 수 없으면 묶음 선언의 `default`, 그것도 없으면 모두 허용. 모르는 필드는 무시. 기록 `module_gate`(`source` = clockout | default | all), `module_skip`.
- `ModuleSources`: 묶음 기본 모듈(실행 파일 옆 `modules\<id>\`)과 받은 모듈(`CLOCKOUT_MODULES_DIR\<id>\<판>\`, 표시 파일 `.clockout-module`이 있는 판 중 가장 높은 것)을 모은다. 판 비교는 `X.Y.Z`를 숫자로(`BridgeUpdatePlan.Compare`, 같은 계산을 두 번 짜지 않음). 판 폴더 이름은 영문·숫자·`.`·`-`·`_` 1~32자, `..` 금지. 같은 id가 두 곳에 있으면 선언 `version`이 높은 쪽(같으면 묶음 기본).

### 4-7. 아이콘 뜻 이름 `icon`
선언에는 **그림 이름이 아니라 뜻 이름**만 쓴다. 지금 뜻 이름: `audit` `book` `cell` `chart` `check` `flow` `format` `graph` `hidden` `history` `info` `keyboard` `layers` `link` `mark` `more` `note` `search` `settings` `sheets` `sum` `table` `tag` `warning`. 사용자가 고른 아이콘 세트가 뜻 이름을 실제 그림으로 바꾼다. 모르는 이름이면 기능 모듈 이름의 첫 글자를 보인다.

## 6. 다리 명령 (`commands`·단추·목록 줄이 보내는 이름)
요청 인자는 `arg.*`로 만든 글자 객체. 응답: `{"ok":true,"proto":0,"data":{}}` 또는 오류. 읽기 전용 원칙의 예외는 "선택과 활성 시트 이동" 뿐이고, 이동은 엑셀의 실행 취소 기록을 지우지 않는다.

### 6-1. 이동·열기 (기본)
| 명령 | 판 | 인자 | 하는 일 |
|---|---|---|---|
| `goto` | 0.0.011 | `{addr, sheet?}` | 칸으로 이동(시트를 먼저 활성화하고 스크롤하며 이동). 선택이 바뀐다. 실패하면 `command_failed`(셀 편집 중 등) |
| `sheet.activate` | 0.0.011 | `{name}` | 시트를 활성화(이름으로만) |
| `book.open` | 0.0.015 | `{name}` | 지금 책과 **같은 폴더**의 엑셀 파일(xls·xlsx·xlsm·xlsb·xlam·csv)을 연다. 이미 열려 있으면 그 창으로. 경로 문자가 든 이름·그 폴더에 없는 파일·엑셀 파일이 아닌 것은 거절. 셀 값을 바꾸지 않는다 |

### 6-2. 틀이 처리하는 명령 (`app.` 접두어)
다리로 보내지 않고 틀이 직접 처리한다. 모듈은 `commands`에 이름을 적으면 쓴다.
| 명령 | 인자 | 하는 일 |
|---|---|---|
| `app.history.back`, `app.history.forward` | 없음 | 발자취 뒤로/앞으로 |
| `app.history.jump` | `{index}` | 발자취의 n번째로 |
| `app.hansu.open` | 없음 | 한 수(함수 도우미) 창 열기 |

### 6-3. 실험 쓰기 명령 (`write.` 접두어)
**공통 규칙**: 틀이 사용자에게 "실험 기능이며 오류가 생길 수 있다"는 안내를 보이고 **확인을 받은 뒤에만** `confirm:"1"`을 붙여 보낸다.
1. `confirm`이 `"1"`이 아니면 어떤 경우에도 엑셀을 바꾸지 않고 **계획**만 돌려준다: `{"phase":"plan","count":N,"summary":"…"}`.
2. `confirm:"1"`이면 **실행**: `{"phase":"apply","changed":N,"message":"…","undoCmd":"…","undoArgs":"{…}"}`. `undoCmd`·`undoArgs`는 되돌릴 수 있을 때만 있다.
3. 입력이 모자라면 `{"phase":"need","needs":[{"key","label","default"}]}`를 돌려주고 틀이 물어 인자에 더해 다시 보낸다.
4. 엑셀 **바깥에서** 쓴 값은 엑셀의 되돌리기(Ctrl+Z)에 들어가지 않는다. 그래서 다리가 바뀐 칸의 옛 내용(수식·값·표시 형식)을 메모리에 두고 `…undo` 명령으로 되돌린다(5000칸까지, 구조를 바꾸는 것은 되돌리기 없음).
5. 아주 숨김 시트·보호된 시트(잠긴 칸)는 건드리지 않고 거절한다.

| 명령 | 판 | 인자 | 하는 일 |
|---|---|---|---|

## 7. 다리 진입점 (VBA, 훈수꾼 틀이 부르는 것)
기능 모듈은 이 함수를 **직접 부르지 않는다.** 틀이 엑셀 인스턴스마다 전용 스레드에서 차례로 부른다. 새 조회·명령을 만드는 사람(다리에 기여하는 사람)이 알아야 할 것.

| 진입점 | 인자 | 반환 | 동작 |
|---|---|---|---|
| `CoHunsu_Hello()` | 없음 | JSON 글 | `version`, `proto`, `queries[]`, `commands[]`, `signals[]`, `office` |
| `CoHunsu_Query(qName, argsJson)` | 조회 이름, 객체 JSON | JSON 글 | 이름으로 `CoHunsuQ_<이름>.bas`의 `Query_<이름>`에 나눠 줌. 도는 동안 신호를 끈다(조회가 일으키는 이벤트는 모두 조회 자신의 것). 모르는 이름은 `query_unknown`, 도중 오류는 `query_failed` |
| `CoHunsu_Do(cmdName, argsJson)` | 명령 이름, 객체 JSON | JSON 글 | `CoHunsuDo_<이름>.bas`로 나눠 줌. 모르는 이름은 `query_unknown`(같은 코드), 도중 오류는 `query_failed` |

- **부르는 법**: `Application.Run "'clockout-hunsu.xlam'!CoHunsu_Query", "selection.summary", "{}"`. 인자와 반환은 모두 문자열(JSON). **표준 모듈(`.bas`)이어야 한다**(`Application.Run`은 클래스 메서드를 못 부른다).
- **약속**: 어떤 상황에서도 엑셀 사용자에게 오류 창을 띄우지 않는다(모든 공개 프로시저가 `On Error`로 감싸 JSON 오류를 돌려준다). 조회는 엑셀 설정(`ScreenUpdating`·`Calculation`·`EnableEvents`)을 바꾸지 않는다. 대화상자(`MsgBox`)를 띄우지 않는다.
- **파일 규칙**: 조회 하나에 파일 하나(`CoHunsuQ_<이름>.bas`, 안의 함수 이름은 모듈 이름과 달라야 한다: `Query_<이름>`), 명령 하나에 파일 하나(`CoHunsuDo_<이름>.bas`). 한 파일 300줄 안팎, 800줄 넘기지 않는다. 소스는 CP949 + CRLF, `Declare`는 `#If VBA7 Then … PtrSafe` 두 갈래, 지역 변수에 예약어(`name`·`out`·`scale` …)를 쓰지 않는다. 범용 함수(범위 훑기·오류 판별·글자 처리)는 다리에 쓰지 않고 공용 `clockout-lib`에 더한 뒤 부른다. JSON 만들기는 `CoHunsuJson`(`CoHunsuJson_Pair`·`_Str`·`_Fail` …)을 쓴다. 모든 조회·명령에는 보이지 않는 엑셀에서 도는 시험을 `tools/test_bridge.ps1`에 더한다.
- **호환**: `proto`(통신 형식 번호, 지금 0)가 틀보다 높으면 틀이 쓰지 않고 업데이트를 안내한다. 조회·명령을 더하면 `hello` 목록에 나타나야 하고, 기능 모듈은 필요한 조회가 목록에 없으면 그 기능 모듈만 쉰다. 다리 판(`vX.Y.Z`)은 기능 모듈 `min_version`과 비교해 `bridge_old`를 정한다.

## 10. 알려진 한계 (이 문서 기준)
- **엑셀에서 다시 실행해 응답을 확인하지 않았다**(5장 응답 예는 소스 머리 주석에서 옮겼다).
- `errors`는 활성 시트만, `flow.neighbors`는 같은 시트만, `flow.graph`·`mark`·`color.sum` 등은 위 표의 한도가 있다. 다른 통합 문서·3D 참조·`INDIRECT`는 못 따라간다.
- `mode` 신호는 지원하지 않는다(엑셀에 편집 이벤트가 없다).
- 부품 `toggle`·`input`·`flow`·`tabs`는 아직 그려지지 않는다(3-3).
- 기능 모듈이 새 설정 키·새 부품·새 표시 모양·새 조회를 스스로 더할 수는 없다. 공용에 요청해야 한다.
- 훈수꾼 소스 저장소는 비공개이므로 이 문서의 구현 이름·경로는 그 저장소 기준이다. 외부 작성자는 이 문서와 카탈로그의 기능 모듈 선언만으로 만들 수 있게 쓰려고 했지만, 시험 도구(`dotnet test`·`test_bridge.ps1`)는 훈수꾼 저장소에서만 돈다.
