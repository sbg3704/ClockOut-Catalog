# 하위 프로그램·기능 모듈 공통 계약 (훈수꾼·캐드선수용 안내)

> 작성일 2026-11-22 · **이 문서가 원본**이다. 훈수꾼·캐드선수처럼 따로 도는 하위 프로그램을 만드는 프로젝트는 이 문서를 읽고, 자기 기준 문서(`기능모듈_제작기준_<하위프로그램>.md`)를 이 폴더에 쓴다. 엑셀 추가기능(VBA) 편은 `기능모듈_제작기준_엑셀VBA.md`.
> 칼퇴 저장소의 상세 규격은 비공개이므로, 외부 작성자와 다른 프로젝트가 알아야 할 것만 여기에 옮겼다.

## 1. 용어 (2026-11-22 사용자 결정)
- **하위 프로그램**: 엑셀 추가기능, 훈수꾼, 캐드선수처럼 칼퇴 레일에서 받아 쓰는 한 덩어리의 프로그램.
- **기능 모듈**: 하위 프로그램에 붙어 일을 하는 낱개 기능.
- 코드·파일 이름에 남은 "하위 모듈", "모듈", "추가기능"은 위 말로 읽는다. 옛 이름은 낸 판이 깨지므로 바꾸지 않는다. 새 문서·화면 글에는 위 용어를 쓴다.

## 2. 왜 이런 계약인가
칼퇴 화면이 바뀔 때마다 훈수꾼·캐드선수를 고쳐야 하면 하나 바꿀 때 프로그램 3개를 고치게 된다. 그래서 **하위 프로그램은 내용만 내고, 화면은 칼퇴가 공통 틀로 그린다.** 칼퇴 화면을 고쳐도 하위 프로그램은 패치 없이 돌아야 한다.

## 3. 원칙 6가지
1. **선언은 내용만 낸다.** 기능 모듈 목록, 켜기/끄기 기본값, 사용법, 패치노트, 설정 항목, 설정창 연결 명령. **화면 모양(탭 순서·색·배치·아이콘 위치)은 넣지 않는다.**
2. **칼퇴와는 `commands`로만 이어진다.** 칼퇴가 하위 프로그램을 부르는 길은 선언의 `commands`에 적힌 명령뿐이다(지금은 `settings` 하나). 화면·내부 함수에 기대지 않는다.
3. **옛 판도 읽는다.** `contract_version`이 없으면 0. 칼퇴는 0도 1도 읽고, 판이 올라가도 옛 칸을 지우지 않는다.
4. **새 칸은 늘 선택 항목이다.** 필수 칸은 늘리지 않는다. 칸이 없는 선언은 계속 유효하다.
5. **모르는 칸은 무시한다.** 칼퇴보다 새 선언이나 화면 모양 칸이 와도 읽기를 거부하지 않고 아는 칸만 읽는다(개발자 설치 때 상태줄에 한 줄 알려 줄 뿐, 설치는 막지 않는다). **읽는 쪽인 하위 프로그램도 칼퇴가 주는 파일·환경변수의 모르는 필드를 무시해야 한다.**
6. **되돌릴 수 없는 변경만 `spec`을 올린다.** `spec`이 칼퇴가 아는 값보다 높으면 "더 새 칼퇴가 필요"로 거부한다. 지금은 0만 있다.

## 4. 칼퇴가 읽는 칸 (하위 프로그램 선언 `<id>.app.json`, 기능 모듈 선언 `module.json` 공통)
| 칸 | 계약 판 | 설명 |
|---|---|---|
| `spec` | 0 | 되돌릴 수 없는 변경 표시(지금 0만) |
| `contract_version` | 1 | 선택. 없으면 0. 이 선언이 따르는 계약 판 |
| `id`, `name`, `version` | 0 | 필수. `version`은 `0.0.045`처럼 점으로 나뉜 숫자(앞의 `v` 없이). **판은 이 `version` 하나가 정한다**(안내문에 판을 따로 적지 않는다). zip을 만들 때마다 올린다 |
| `modules` | 0 | 선택. 기능 모듈 목록 `[{id, name, summary, default, memoryMb, startMs}]`. id는 영문·숫자·`-`·`_`, 최대 64개, 중복 불가, `default` 생략 시 true |
| `settings` | 0 | 선택. 전용 설정창이 없는 프로그램의 설정 항목 `[{id, label, summary, type, default, min, max, choices, module}]`. `type`은 `bool`·`text`(최대 256자)·`number`(min·max)·`choice`(`choices` 필수). `default`는 글로 적는다. 최대 64개 |
| `memoryMb`, `startMs` | 0 | 선택. 칼퇴 계기판에 보일 메모리·시작 시간 선언(프로그램·기능 모듈별) |
| `guide`, `changes` | 0 | 선택. 사용법·패치노트 파일 경로. 없으면 묶음 맨 위의 `<id>.guide.md`·`<id>.changes.md`를 찾는다 |
| `settingsArgs` | 0 | 옛 이름의 설정창 실행 인자. 계속 읽는다 |
| `commands` | 1 | 선택 **객체**. 키는 아래 5장. 모르는 키·모양이면 없는 것으로 본다 |

## 5. `commands`
```json
"contract_version": 1,
"commands": { "settings": ["--settings"] }
```
- `settings`: 문자열 배열(1~16개, 각 200자 이하). 있으면 소개 화면에 **[설정창 열기]**가 나오고, 같은 exe에 이 인자를 붙여 켠다.
- 우선순위: `commands.settings`가 있으면 그것, 없으면 옛 `settingsArgs`. 둘 다 있어도 오류가 아니다.
- 모양이 틀린 `commands`(배열·문자열·빈 배열·숫자 요소 등)는 오류가 아니라 없는 것으로 보고 `settingsArgs`로 되돌아간다.
- **엑셀 추가기능 선언의 `commands`(단축키 명령 배열)와 다르다.** 추가기능 선언은 배열, 하위 프로그램 선언은 객체이며 서로 읽지 않는다.
- 새 명령은 이 객체에 키를 더하는 식으로만 늘린다(예: 나중에 `restart`). 칼퇴가 모르는 키는 무시되므로 먼저 낸 선언이 옛 칼퇴에서도 안전하다.

## 6. 칼퇴가 하위 프로그램에 주는 것 (읽는 쪽 규칙)
칼퇴는 하위 프로그램을 켤 때(그리고 기능 모듈 스위치·설정을 바꿀 때마다) 파일을 쓰고 경로를 환경변수로 넘긴다. 하위 프로그램은 시작할 때 읽는다. 환경변수나 파일이 없으면(단독 실행) 선언의 `default`를 따른다.

| 환경변수 | 파일 | 내용 |
|---|---|---|
| `CLOCKOUT_MODULES_FILE` | `modules.enabled.json` | `{ "spec": 0, "enabled": ["summary", "check"] }`. **`enabled`에 없는 기능 모듈은 아예 불러오지 않는다**(끄면 메모리·시작 시간이 줄어든다) |
| `CLOCKOUT_SETTINGS_FILE` | `settings.values.json` | `{ "spec": 0, "values": { "auto": true, "size": 16, "theme": "밝게" } }` (bool·숫자·글). 선언에서 사라진 항목의 옛 값은 넣지 않는다 |
| `CLOCKOUT_MODULES_DIR` | 폴더 | 칼퇴가 설치한 기능 모듈이 있는 폴더(`<기능 모듈 id>\<판>\` 아래). 하위 프로그램이 여기서 기능 모듈을 읽는다 |

- 필드는 더할 수는 있어도 **지우거나 뜻을 바꾸지 않는다.** 읽는 쪽은 모르는 필드를 무시하고, 새 필드가 와도 죽지 않아야 한다.
- 바뀐 선택은 하위 프로그램을 껐다 켜면 반영된다(칼퇴가 [지금 다시 켜기]를 보여 준다). 파일 변경을 감시해 즉시 반영하는 것은 선택 사항이다.

## 7. 사용법·패치노트 (소개 화면)
- 묶음 맨 위 `<id>.app.json` 옆에 `<id>.guide.md`(사용법)·`<id>.changes.md`(패치노트)를 둔다. 둘 다 선택이며 없어도 설치·켜기·끄기는 된다.
- 칼퇴는 설치된 판 폴더에서 읽으므로 판을 바꾸면 안내문도 그 판 것으로 바뀐다.
- 다른 이름·자리에 두려면 `guide`·`changes` 칸에 묶음 안 상대 경로(`/` 구분, `..`·절대 경로·드라이브 글자 금지, `.md` 또는 `.txt`)를 적는다. 틀리면 그 칸만 "없음"으로 보인다.

## 8. 배포와 인증
- 하위 프로그램과 그 기능 모듈은 이 저장소 `catalog.json`을 거쳐 칼퇴가 받는다. 바이너리는 저장소에 커밋하지 않고 Release 파일로 올린다(받을 파일은 `.zip`, SHA-256 필수).
  - 하위 프로그램은 `apps` 구역(`id`·`name`·`version`·`url`·`sha256` 필수, `summary`·`description`·`preview`·`size`·`requires`·`host` 선택).
  - 기능 모듈은 하위 프로그램별로 `app`(소속 하위 프로그램 id)을 적어 올린다: `modules[{app,id,name,version,summary,author,url,sha256,size,kind("module"|"library")}]`, 묶음 `modulePacks[{app,id,name,summary,modules[]}]`.
- 받아도 되는 주소는 이 저장소의 Release와 raw 파일뿐이다(허용되지 않은 주소·`..`·https 아님은 건너뜀). 받은 파일의 SHA-256이 다르면 지우고 설치하지 않는다. 한도: 기능 모듈 zip 200MB 이하.
- **인증**: 운영자가 확인한 id·판·SHA-256과 일치하는 기능 모듈만 "인증"으로 보인다. 일치하지 않거나 확인 목록에 없으면 **미인증**이라 기본으로 숨기고, 설치하려면 "인증되지 않은 기능 모듈이며 생기는 문제는 사용자 책임"이라는 경고에 동의해야 한다. 개발자 모드에서는 내 기능 모듈이 인증 없이도 배제되지 않는다. (이 인증 확인 기능은 칼퇴에서 단계적으로 구현 중이다.)
- 비밀값(토큰, 키, 비밀번호)·회사 자료는 올리지 않는다.

## 9. 각 프로젝트가 자기 기준 문서에 써야 할 항목 (공용 라이브러리 함수 설명서 포함)
훈수꾼·캐드선수는 `기능모듈_제작기준_<하위프로그램>.md`에 아래를 쓴다. 이 문서(공통 계약)의 3~8장은 베껴 쓰지 말고 링크만 건다. 엑셀VBA 편의 구성(0~11장)이 본보기다.

1. **무엇이 기능 모듈인가**: 이 하위 프로그램에서 기능 모듈 한 개의 단위와 형태(훈수꾼은 선언형 `view.json` 모듈, 캐드선수는 `module.json` 선언 + 리습·플러그인 등 각자 정함)와 id 규칙.
2. **폴더·파일 구성**: 소스 위치, 필수·선택 파일, 파일 크기·책임 규칙, 맨 위 한국어 주석.
3. **선언 칸**: 4장 공통 칸 외에 이 하위 프로그램만 쓰는 칸. 새 칸은 모두 선택 항목이어야 하고 필수 칸을 늘리지 않는다.
4. **받는 환경**: 6장 환경변수·파일을 어떻게 읽는지, 모르는 필드 무시, 단독 실행 때의 기본값.
5. **의존·공용 부품**: 어떤 공용 라이브러리를 먼저 쓰는지, 의존 선언(`id`·`min_version`·`reason`), 같은 코드를 두 번 짜지 않는 규칙.
5-1. **공용 라이브러리 함수 설명서(필수, 자세히)**: 통합 라이브러리를 만든 의미가 있으려면 쓰는 사람이 함수를 찾아 바로 쓸 수 있어야 한다. 그 하위 프로그램이 쓰는 공용 라이브러리마다 **함수(또는 API) 목록, 인자와 반환값, 동작, 부르는 법(참조 설정·진입점·환경), 짧은 예제**를 적는다. 별도 파일 `공용라이브러리_함수설명서_<하위프로그램>.md`로 나눠도 된다. 소스에서 뽑아 쓰고, 라이브러리를 고치면 같은 PR에서 갱신한다. 엑셀VBA 편 `공용라이브러리_함수설명서.md`가 본보기다.
6. **하위 호환**: 이 하위 프로그램에서 "낸 뒤 바꾸지 않는 것"의 목록(공개 이름·설정 키·파일 형식)과 판 번호 무게(+1/+10/+100).
7. **안전**: 실행 파일 거부, 경로 탈출 금지, 밖에서 온 값 검사, 되돌릴 수 없는 일은 확인, 오프라인 동작.
8. **빌드·시험**: 어떤 환경에서 무엇을 어떻게 빌드·시험하는지, 클라우드에서 못 하는 확인은 PR에 솔직히 적는 규칙.
9. **올리는 방법**: 카탈로그 항목 예시, 올리는 순서(Release 먼저, 카탈로그 나중), PR 본문 양식, 점검표.
10. **외부 코드 규칙**: 허용형 라이선스만, 판 고정, 출처 기록.
11. **알려진 한계·확인 범위**.

## 10. 해야 할 일 (하위 프로그램 프로젝트별)
- **훈수꾼**: 선언 맨 위에 `"contract_version": 1`을 더하고, 설정창 인자를 `commands.settings`로 옮긴다(옛 `settingsArgs`도 계속 읽으니 서두르지 않아도 된다). `기능모듈_제작기준_훈수꾼.md`와 공용 라이브러리 함수 설명서(9장 5-1)를 쓴다.
- **캐드선수**: 같은 변경과, 기능 모듈 선언(`module.json`) 기준 문서 `기능모듈_제작기준_캐드선수.md`와 공용 라이브러리 함수 설명서(9장 5-1)를 쓴다. 캐드는 플러그인만 읽고, 칼퇴에서 켠 기능 모듈만 플러그인이 불러온다는 구조를 문서에 적는다.
- **칼퇴**: 계약 칸을 더할 때는 선택 칸으로만 더하고 이 문서를 같은 PR에서 갱신한다.
- 새 기능이 칼퇴 쪽에 필요하면 선언에 칸을 지어내지 말고 칼퇴 쪽 개편 요청으로 낸다.
