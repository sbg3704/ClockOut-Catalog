# 기능 모듈 제작 기준: 훈수꾼 편

> 작성일 2026-11-22 · 훈수꾼 0.0.267 기준. 이 문서는 **훈수꾼이라는 하위 프로그램에 붙는 기능 모듈**을 만드는 기준이다. 사람이 직접 짜든 AI에게 시키든 같은 기준을 따른다. AI에게는 이 문서와 `공용라이브러리_함수설명서_훈수꾼.md`를 함께 지침으로 붙여 넣는다.
> 공통 계약(칼퇴가 읽는 칸, 환경변수, 배포·인증)은 `하위프로그램_기능모듈_공통계약.md`가 원본이라 여기에 베끼지 않는다. 본보기 구성은 `기능모듈_제작기준_엑셀VBA.md`.
> 훈수꾼 소스 저장소는 비공개다. 이 문서는 **기능 모듈을 만드는 쪽에 필요한 것**(선언, 부품, 다리 조회·명령, 올리는 법)만 담는다. 소스와 다르면 소스가 이긴다.
> **확인 범위**: 훈수꾼 소스·선언 27개·시험을 읽어 정리했다. 이 문서를 쓰면서 새 기능 모듈을 실제로 빌드해 칼퇴로 받아 켜 보지는 못했다(11장).

## 0. 용어

| 말 | 뜻 |
|---|---|
| **훈수꾼** | 엑셀 창 위에 겹쳐 떠서 선택 요약·오류·수식 흐름 같은 훈수를 보여 주는 하위 프로그램(코드 이름 `hunsu`) |
| **기능 모듈** | 훈수꾼에 붙는 낱개 기능 하나. 코드 없이 **선언 파일**만으로 이루어진다 |
| **다리** | 엑셀 안에서 도는 VBA 추가기능 `clockout-hunsu`. 훈수꾼과 엑셀 사이의 모든 통신이 여기를 지난다. 기능 모듈은 다리가 아는 **조회**(읽기)와 **명령**(이동·실험 쓰기)만 쓴다 |
| **틀**(셸) | 훈수꾼 프로그램 본체. 창 만들기, 따라다니기, 숨기기, 저장, 단축키, 옵션 창을 모두 틀이 한다 |

- 코드·파일 이름에 남은 말: 훈수꾼 쪽에서는 기능 모듈을 지금도 "모듈"(`modules/` 폴더, `hunsu-<이름>` id), 칼퇴 쪽 선언에서는 `modules`·"하위 모듈"이라 적는다. 모두 이 문서의 "기능 모듈"과 같다. 이미 낸 이름은 바꾸지 않는다(7장).
- id는 `hunsu-<영문 소문자·숫자>(-<영문 소문자·숫자>)*` 모양이다. 예: `hunsu-errors`, `hunsu-flowgraph`. 이 모양이 아니면 훈수꾼이 읽지 않는다. 칼퇴에 올릴 때의 id 규칙(영문·숫자·`-`·`_`, 64자 이하)도 이 모양이면 만족한다.

## 1. 먼저 알아 둘 것
1. **같은 일을 하는 기능 모듈이 이미 있는지** 본다. 지금 기본으로 든 것은 27개다(선택 요약·책 정보·셀 정보·오류 셀·수식 흐름·색연필 수식 흐름·값 정리·한 수 …). 목록은 훈수꾼 묶음의 `hunsu.app.json`(`modules`)에 있고, 칼퇴 [모듈 관리]에서도 보인다.
2. **코드를 쓰고 싶어지면 멈춘다.** 기능 모듈은 코드를 실행하지 못한다. 맞는 선언 칸이 없으면 기능 모듈 안에서 우회하지 말고 **공용(틀·다리)에 칸을 더해 달라고 제안**한다(5장). 새 기능 때문에 틀을 고쳐야 한다면 그것이 빠진 공용 부품이다.
3. **직접 다 짜지 않는다.** 엑셀에서 값을 읽어 오는 일은 다리 조회가 이미 하는 것이 많다(함수설명서 4장). 새 조회가 정말 필요하면 다리에 조회를 더해 달라고 제안한다.
4. 회사 자료·비밀값(토큰, 키, 비밀번호)·개인 정보는 올리지 않는다. 시험 자료는 가짜 자료만 쓴다.
5. **클라우드(Linux)에서는 훈수꾼 화면도 엑셀도 볼 수 없다.** 선언이 읽히는지(문법·시험)는 클라우드에서 확인되지만, 화면 모양과 엑셀에서 나오는 값은 Windows PC의 엑셀에서만 확인된다. **확인한 범위와 못 한 범위를 PR에 솔직히 적는다.**
6. 사용자 PC에서 키보드·마우스를 대신 조작하지 않는다. 엑셀 시험은 보이지 않는 엑셀을 COM으로만 부른다(훈수꾼의 `test_bridge` 방식).

## 2. 폴더와 파일

기능 모듈 하나가 폴더 하나다. 폴더 이름 = 선언의 `id` = 선언 파일 이름의 앞부분이어야 한다.

```
hunsu-errors/
  hunsu-errors.hunsu.json     선언(3장)   ← 필수
  view.json                   화면 선언(4장) ← 사실상 필수(없으면 빈 화면)
  README.md                   사람이 읽는 설명(선택, 8장)
```

| 항목 | 규칙 |
|---|---|
| 선언 파일 이름 | `<id>.hunsu.json`. 칼퇴 쪽 선언 `<id>.app.json`(하위 프로그램)·`module.json`(저장소 목록)과 **다른 파일**이다 |
| 크기 | `<id>.hunsu.json`과 `view.json` 각각 **64KB 이하**. 넘으면 그 기능 모듈은 읽지 않는다(작업 기록 `manifest_bad`, `64KB_초과`) |
| 글자 | UTF-8. JSON에는 주석을 쓸 수 없다. 설명은 `description`과 README에 적는다 |
| 한 파일 한 책임 | 선언은 "무엇을 보일지"와 "어디에 어떤 모양으로"만 적는다. 한 기능 모듈이 두 가지 일을 하면 둘로 나눈다 |
| 코드·바이너리 | 기능 모듈 폴더에는 JSON과 README뿐이다. `.exe`·`.dll`·`.bat`·`.cmd`·`.vbs`·`.ps1`·`.xlam` 같은 실행 파일은 두지 않는다(훈수꾼은 선언 두 파일만 읽고 그 밖의 파일은 쓰지 않는다. 9장) |
| 새 설정 파일 | 기능 모듈은 자기 설정 파일을 만들지 않는다. 사용자가 바꾸는 값은 `quick`(3장)으로 선언하고 저장은 틀이 한다 |

**본뜰 만한 기능 모듈**: 상태 `hunsu-selection`, 목록 `hunsu-errors`, 셀 위 그림 `hunsu-marks`, 따라다니는 글 `hunsu-selection`의 `hud`.

## 3. 선언 파일 `<id>.hunsu.json`

```json
{
  "spec": 0,
  "id": "hunsu-errors",
  "name": "오류 셀",
  "version": "0.1.000",
  "host": "excel",
  "category": "점검",
  "author": "ClockOut",
  "description": "지금 시트의 오류 셀(#DIV/0!, #REF! 등)을 모아 보여 주고, 누르면 그 칸으로 이동합니다.",
  "dependencies": [
    {"id": "clockout-hunsu", "min_version": "0.0.011", "reason": "오류 셀 조회(errors)와 이동(goto)에 훈수꾼 다리를 씁니다"}
  ],
  "shapes": ["tab", "panel", "window"],
  "place": "edge-left",
  "order": 200,
  "icon": "warning",
  "data": [
    {"topic": "errors", "on": ["change", "calc", "sheet", "book"], "weight": "normal"}
  ],
  "quick": [{"kind": "choice", "key": "listMaxRows", "label": "목록에 한 번에 보일 줄 수", "group": "목록",
             "options": [{"value": "20", "label": "20"}, {"value": "50", "label": "50 (기본)"}]}],
  "commands": ["goto"]
}
```

### 3-1. 필수 칸 (없거나 틀리면 그 기능 모듈만 건너뛴다)
| 칸 | 규칙 |
|---|---|
| `spec` | 0. 훈수꾼이 아는 값보다 높으면 `spec_newer`로 건너뛴다. 되돌릴 수 없는 규격 변경 때만 올라간다(7장) |
| `id` | 위 0장 모양. 폴더 이름과 같아야 한다 |
| `name`, `version`, `category`, `author`, `description` | 비어 있으면 안 된다. `version`은 `X.Y.Z`(앞의 `v` 없이) |
| `host` | `"excel"` |
| `dependencies` | **배열이어야 한다**(비어 있어도 `[]`로 둔다). 쓰는 다리의 최소 판을 적는다(5장) |
| `shapes` | 모양 목록. 아는 모양: `mark`·`chip`·`tab`·`panel`·`window`. **`panel`과 `window` 중 하나는 반드시** 있어야 한다(`window`가 없으면 틀이 `panel`을 창 안에 넣는다) |
| `place` | 처음 놓일 자리(3-3). 그 자리에 놓을 모양이 `shapes`에 있어야 한다 |

### 3-2. 선택 칸
| 칸 | 설명 |
|---|---|
| `order` | 자리 안 순서. 작을수록 앞. 기본 500. 100 단위로 띄워 쓰고 아래 3-4 범위를 따른다 |
| `icon` | 아이콘의 **뜻 이름**(`sum`·`warning`·`sheets`·`flow`·`tag`·`audit`·`book`·`keyboard`·`graph`·`history`·`mark` 등). 그림은 사용자가 고른 아이콘 세트가 정한다. 없으면 이름 첫 글자 |
| `form` | 처음 보이는 모양: `panel`(기본, 도크 패널) · `hud`(처음부터 떼어 낸 반투명 창, `shapes`에 `window` 필요) · `mini`(줄여서 시작). 사용자가 옮기거나 바꾸면 사용자 값이 이긴다 |
| `size` | `form: "hud"`일 때 처음 창 크기 `{"width": 120~800, "height": 60~800}` |
| `data` | 엑셀에서 받을 값 구독 `[{topic, on[], weight}]`. 3-5 |
| `hud` | 커서·고른 칸 옆을 따라다니는 글. 3-6 |
| `quick` | 우클릭 빠른 설정과 설정 창 [옵션] 쪽 항목. 3-7 |
| `commands` | 이 기능 모듈이 다리에 보내도 되는 **명령 이름 허용 목록**. 여기 없는 명령은 단추·목록 줄을 눌러도 보내지 않는다. 3-8 |
| `scope`, `params` | 지금 틀이 읽지 않는다(모르는 칸이라 무시). 기존 선언에 들어 있어도 되고 없어도 된다. 사용자가 바꿀 값은 `quick`을 쓴다 |

> 모르는 칸은 훈수꾼이 무시한다(오류가 아니다). 그렇다고 칸을 지어내지 않는다. 새 기능이 필요하면 5장의 절차로 공용에 요청한다.

### 3-3. 자리(`place`)
| 자리 코드 | 쓰는 모양 | 뜻 |
|---|---|---|
| `edge-left` | tab, panel | **기본.** 왼쪽 독(훈 원·아이콘)에 붙고 열린 패널은 그 오른쪽에 뜬다. 지금 기본 기능 모듈 27개가 모두 이 자리다 |
| `edge-right` | tab, panel | 오른쪽 독. 사용자가 모듈 관리에서 [오른]으로 옮겼을 때만 쓰이므로 선언의 기본값으로는 쓰지 않는다 |
| `mark` | mark | 셀 위 표시층 |
| `strip` | chip | 상시 띠 |
| `summon`, `pin`, `second` | window, panel | 호출층·핀 창·보조 모니터 |

사용자가 정한 자리·순서·켜고 끈 것이 선언보다 먼저다(기능 모듈을 업데이트해도 유지된다).

### 3-4. 분류와 순서 권장
| 분류 | 넣는 것 | `order` |
|---|---|---|
| 요약 / 상태 | 선택 요약, 책 정보, 계산 모드 경고 | 100번대 |
| 점검 | 오류 셀, 깨진 링크, 숨은 시트 | 200번대 |
| 이동 | 시트 이동, 이름 범위, 최근 위치 | 300번대 |
| 수식 | 흐름도, 참조 보기 | 400번대 |
| 고치기 | 쓰기 도구(실험) | 400번대 |
| 참고 | 메모, 단축키 표 | 900번대 |

새 분류는 기능 모듈이 세 개 이상 모일 때만 만든다. 분류는 선언에서 읽을 뿐 코드에 박혀 있지 않다.

### 3-5. 데이터 구독 `data`
```json
"data": [{"topic": "errors", "on": ["change", "calc", "sheet", "book"], "weight": "normal"}]
```
- `topic`: 다리 **조회 이름**(함수설명서 4장). 모르는 이름이면 그 기능 모듈만 쉰다(`query_unknown`). `app.`으로 시작하는 주제(예: `app.history`)는 틀이 직접 채우는 것이라 다리에 묻지 않는다.
- `on`: 어떤 신호가 오면 다시 물을지. 신호: `sel`(선택 바뀜) · `change`(값 바뀜) · `sheet`(시트 전환) · `book`(책 열림·닫힘·전환) · `calc`(계산 끝). `mode`(편집 시작·끝)는 정확히 지원되지 않아 쓰지 않는다.
- `weight`: 엑셀을 얼마나 바쁘게 하는 조회인가. **엑셀을 느리게 하지 않는 것이 먼저**다. 틀이 무게에 따라 조회를 늦추거나 건너뛴다.
  | 무게 | 뜻 | 틀의 처리 |
  |---|---|---|
  | `light`(기본) | 선택 영역만 보는 조회 | 신호 뒤 곧바로 조회 |
  | `normal` | 시트 하나를 훑는 조회 | 입력이 잠깐 멈추면 조회, 보이는 기능 모듈만 |
  | `heavy` | 책 전체나 참조 관계를 따라가는 조회 | 사용자가 열었을 때와 새로 고침을 눌렀을 때만 |
- 끈 기능 모듈은 조회하지 않는다(엑셀을 바쁘게 하지 않는다).

### 3-6. 따라다니는 글 `hud`
커서 옆이나 고른 칸 옆에 글을 띄운다. 창·따라다니기·숨기기는 틀이 하고, 기능 모듈은 **어디에 붙을지와 무슨 글인지**만 적는다.
```json
"form": "hud", "size": {"width": 250, "height": 170},
"hud": {"anchor": "cursor", "enabledKey": "cursorHud", "anchorKey": "hudAnchor",
        "when": "selection.summary.count > 0", "join": " · ",
        "parts": [{"text": "합계 {selection.summary.sum:n}", "when": "selection.summary.sum != null"},
                  {"text": "{selection.summary.count:n0}칸", "when": "selection.summary.sum == null"}]}
```
- `anchor`: `cursor`(범위를 끄는 동안) 또는 `cell`(고른 칸 옆 계속). `anchorKey`가 가리키는 설정이 있으면 그 값이 우선이라 사용자가 바꿀 수 있다.
- `enabledKey`(선택): 켜고 끄는 설정 키. 없으면 늘 켜짐. `when`(선택): 보일 조건. `parts[]`: 글 조각(조각마다 `when` 선택), `join`으로 이음(기본 빈 글). 조각이 모두 비면 안 보인다.
- 글 틀과 조건 문법은 함수설명서 2장(코드 실행 없음).

### 3-7. 옵션 `quick` (우클릭 빠른 설정 + [옵션] 쪽)
모듈마다 메뉴·창 코드를 짜지 않는다. 항목을 선언하면 우클릭 메뉴와 설정 창 [옵션]이 같은 선언으로 알아서 그린다.
```json
"quick": [
  {"kind": "toggle", "key": "pencilDraw", "label": "그리기 켜기 (Ctrl+Alt+D)", "group": "그리기", "order": 1, "hotkey": "Ctrl+Alt+D", "apply": "redraw"},
  {"kind": "choice", "key": "pencilLook", "label": "그림 모양", "group": "그리기", "order": 2,
   "options": [{"value": "pencil", "label": "색연필"}, {"value": "marker", "label": "형광 마커"}]},
  {"kind": "menu", "label": "고급", "items": [ {"kind": "toggle", "key": "...", "label": "..."} ]}
]
```
- `kind`: `toggle`(체크) · `choice`(여러 값 중 하나, `options` 2개 이상) · `menu`(하위 메뉴, `items` 필요). `label`은 필수, `toggle`·`choice`는 `key` 필수.
- `key`는 훈수꾼 설정(`settings.json`)의 키다. **기능 모듈이 새 설정 키를 만들 수는 없다.** 이미 있는 키만 쓴다(함수설명서 3-3). 새 키가 필요하면 5장의 절차로 요청한다(훈수꾼 쪽이 설정 속성과 범위 검사를 더한다).
- `hotkey`(toggle 전용, 선택): 전역 단축키. 엑셀이 앞일 때만 등록되고 훈 원 우클릭 메뉴에도 자동으로 들어간다. 규칙은 함수설명서 3-2: **Ctrl 또는 Alt를 반드시 포함**, 키는 A~Z·0~9·F1~F12 하나, 훈수꾼 자체 키 Ctrl+Alt+H·Ctrl+Alt+Shift+H와 겹치면 거절. 같은 키를 두 기능 모듈이 선언하면 앞선 기능 모듈 것만 쓴다.
- `apply`(선택): 값이 바뀐 뒤 틀이 할 일. `redraw`(셀 위 그림을 다시 그림) · `refresh`(켜진 주제를 엑셀에 다시 묻고 다시 그림). 없으면 저장만.
- `order`·`group`(선택): 순서와 묶음 제목. 같은 `group`끼리 구분선과 작은 제목으로 묶인다.

### 3-8. 명령 `commands`
```json
"commands": ["goto"]
```
- 단추·목록 줄을 눌렀을 때 다리에 보낼 수 있는 **명령 이름의 허용 목록**이다. view.json의 `command`가 여기 없으면 보내지 않는다(기능 모듈이 몰래 다른 명령을 부르지 못하게).
- 명령 이름과 인자는 함수설명서 5장. 읽기 전용 이동(`goto`, `sheet.activate`, `book.open`)이 기본이고, `write.`로 시작하는 쓰기 명령은 **실험 기능**이다(안전 7장).

## 4. 화면 선언 `view.json`

```json
{
  "tab": {"title": "오류", "badge": "{errors.count:n0}", "tone": "warn"},
  "panel": [
    {"type": "stat", "value": "{errors.count:n0}", "label": "오류 셀 · {errors.sheet}", "tone": "bad", "showWhen": "errors.count > 0"},
    {"type": "list", "items": "errors.items", "text": "{item.addr}", "sub": "{item.label}", "tone": "bad",
     "command": "goto", "arg.addr": "{item.addr}", "max": 8, "emptyText": "이 시트에는 오류 셀이 없습니다."},
    {"type": "text", "text": "칸을 누르면 그곳으로 이동합니다.", "tone": "muted", "showWhen": "errors.count > 0"}
  ],
  "marks": [ {"items": "mark.errors", "style": "outline", "tone": "bad"} ]
}
```
- `tab`: 접힌 손잡이. `title`(이름), `badge`(숫자 하나, 글 틀), `tone`.
- `panel[]`: 부품 목록(위에서 아래로 쌓인다). 부품 종류와 칸은 함수설명서 2장. **모르는 부품·톤은 그 줄만 건너뛰고 기록**한다(`view_warn`). JSON이 깨졌으면 `view_failed`로 그 기능 모듈이 건너뛰어진다.
- `marks[]`: 셀 위 표시층. `items`는 칸 자리 배열의 데이터 경로(예: `mark.errors`)라서 선언 `data`에 `mark` 조회를 구독해야 한다(`hunsu-marks`가 본보기). `style`: `outline`(테두리) · `fill`(옅은 칠) · `underline`(밑줄) · `pencil`(손으로 그린 색연필 수식 흐름, `role` 필요). 같은 칸 모양은 함수설명서 2장.
- 모든 글·숫자는 **글 틀**(`{주제.경로:형식}`)과 **조건**(`showWhen`·`when`·`activeWhen`)으로만 채운다. 계산·함수·반복은 선언에 쓸 수 없다. 값이 모자라면 다리 조회에서 숫자를 더해 달라고 요청한다.
- 색·글자 크기는 `tone`(`info`·`good`·`warn`·`bad`·`muted`)으로만 고른다. **색 숫자(#RRGGBB)나 글꼴을 선언에 적지 않는다**(화면 모양은 틀의 테마가 정한다. 그래서 칼퇴·훈수꾼 화면이 바뀌어도 기능 모듈을 고치지 않는다).

## 5. 의존과 공용 부품

- 방향은 한쪽뿐이다: **기능 모듈 → 공용(틀의 부품, 다리의 조회·명령).** 틀이 기능 모듈을 이름으로 알지 않고, 기능 모듈끼리 서로의 값에 기대지 않는다. 각자 자기 `data`를 구독한다.
- 선언의 `dependencies`에 **쓰는 다리의 최소 판**을 적는다.
  ```json
  "dependencies": [{"id": "clockout-hunsu", "min_version": "0.0.011", "reason": "…"}]
  ```
  `min_version`은 기능 모듈이 쓰는 조회·명령이 **처음 생긴 다리 판**이다(함수설명서 4·5장의 "판" 칸). 다리 판이 낮으면 `bridge_old`로 그 기능 모듈만 쉬고 업데이트를 안내한다.
- **같은 코드를 두 번 짜지 않는다.** 기능 모듈이 하는 일은 "무엇을 보일지"뿐이다. 창, 따라다니기, 단축키, 옵션 창, 제목줄 단추, 스크롤, 최소화, 저장은 전부 틀의 공용 부품이다.
- 맞는 부품·조회·명령이 없을 때의 순서:
  1. `공용라이브러리_함수설명서_훈수꾼.md`에서 먼저 찾는다.
  2. 없으면 기능 모듈 안에서 우회하지 않는다.
  3. 훈수꾼 저장소에 **공용 칸을 더해 달라는 이슈 또는 PR**을 낸다(틀의 부품 → `Core` 순수 계산 + 시험, 엑셀에서 읽을 값 → 다리 `CoHunsuQ_<이름>.bas` 조회 하나에 파일 하나). 공용에 들어온 뒤 기능 모듈이 그 칸을 쓴다.
- 새 조회는 훈수꾼 다리의 `hello` 목록에 나타나야 하고, 같은 PR에서 함수설명서 4장·다리 규격 문서를 고친다.
- 직접 다 짜지 않는다: 쓸 만한 공개 코드가 있으면 활용한다(10장).

## 6. 받는 환경 (칼퇴가 훈수꾼에 주는 것)
공통 계약 6장이 원본이다. 훈수꾼 쪽 동작만 적는다.

| 환경변수 | 훈수꾼의 읽는 법 |
|---|---|
| `CLOCKOUT_MODULES_FILE` (`modules.enabled.json`) | 시작할 때 읽는다. `enabled`에 없는 기능 모듈은 **선언 파일도 읽지 않고** 건너뛴다(메모리·시작 시간이 줄어든다). 파일이 없거나 64KB를 넘거나 JSON이 깨졌거나 `spec`이 0이 아니거나 `enabled`가 글자 배열이 아니면 묶음 선언(`hunsu.app.json`)의 `default`를, 그것도 없으면 모두 불러온다. 칼퇴가 모르는 기능 모듈(사용자가 폴더에 직접 넣은 것)은 늘 불러온다. 모르는 필드는 무시한다 |
| `CLOCKOUT_MODULES_DIR` | 칼퇴가 카탈로그에서 받아 푼 기능 모듈 폴더(`<id>\<판>\`). 풀기가 끝난 판에는 표시 파일 `.clockout-module`이 있다. 훈수꾼은 id마다 **표시 파일이 있는 가장 높은 판 하나**만 읽는다. **같은 id가 묶음 기본에도 있으면 선언 `version`이 더 높은 쪽**을 쓰고, 같거나 못 읽으면 묶음 기본을 둔다(옛 판으로 되돌아가지 않게) |
| `CLOCKOUT_SETTINGS_FILE` | **읽지 않는다.** 훈수꾼은 자체 설정 창을 쓰고(`commands.settings: ["--settings"]`) 칼퇴가 설정 칸을 그리지 않는다 |
| (환경변수 없음, 단독 실행) | 선언의 `default`를 따르고, 선언이 없으면 모든 기능 모듈을 불러온다 |

- 켜고 끈 선택은 **훈수꾼을 껐다 켜면 반영**된다(파일 감시 없음).
- 칼퇴의 켜고 끄기는 "불러오기"이고, 훈수꾼 설정 창 [모듈]의 켜고 끄기는 "보이기"로 따로다. 처음 보이는 것은 사용자 설정(`enabledByDefault`)이 정한다. 기능 모듈이 스스로 "나는 기본으로 켜져 있어야 한다"를 선언할 수 없다.
- 받은 기능 모듈도 같은 64KB·선언 검사를 거치고 코드를 실행하지 못한다.

## 7. 하위 호환과 판 번호 (가장 중요)
칼퇴·훈수꾼·다리 판이 올라가도 이미 낸 기능 모듈은 고치지 않고 계속 돌아야 한다. 모듈화하는 이유가 이것이다. 공통 원칙(공통 계약 3장)에 더해 훈수꾼에서 **낸 뒤 바꾸지 않는 것**:

| 낸 뒤 바꾸지 않는 것 | 이유 |
|---|---|
| 기능 모듈 `id` | 사용자가 정한 자리·순서·켜고 끈 것, 칼퇴의 켜기 선택이 id에 묶여 있다 |
| 다리 조회·명령 **이름과 뜻**, 응답 칸의 이름·뜻 | 한번 공개한 이름은 뜻을 바꾸지 않는다. 바꿔야 하면 새 이름으로 더한다. 칸은 더하기만 한다 |
| 신호 이름(`sel`·`change`·`sheet`·`book`·`calc`)과 오류 코드(`excel_busy`, `bridge_old`, `query_unknown` …) | 같음 |
| 부품 `type` 이름과 그 칸의 뜻, `tone` 이름, 선언 칸 이름 | 낸 선언이 깨진다. 칸은 더하기만 한다 |
| 설정 키 이름과 기본값의 뜻 | 바꿔야 하면 새 키를 쓰고 옛 키를 읽어 넘겨받는다 |
| 아이콘 뜻 이름 | 바꾸면 모든 아이콘 세트가 어긋난다 |

- **선언에는 이 문서의 칸만 쓴다. 새 칸은 늘 선택 항목**이고 필수 칸은 늘리지 않는다. 틀이 새 칸을 더해도 칸이 없는 옛 선언은 계속 유효하다.
- `spec`은 되돌릴 수 없는 변경에만 올린다. 일반 추가로는 올리지 않는다(지금 0만 있다).
- **판 번호**: 기능 모듈 `version`은 `X.Y.Z`. 고침 +1, 새 기능 덩어리 +10, 구조 변경 +100 정도의 무게로 올린다. **같은 id·판을 다시 올리면 파일 해시가 달라져 칼퇴가 설치를 거부한다.** 고칠 일은 판을 올려 새 Release로 낸다.
- 칼퇴에 알리고 싶은 새 기능은 선언 칸을 지어내지 말고 칼퇴 쪽 개편 요청으로 낸다(공통 계약 10장).

## 8. README
기능 모듈 폴더의 `README.md`(선택이지만 권장)에 적을 것: 하는 일(한두 문단) / 어디서 보이는가(자리·모양·단축키) / 설정(`quick`으로 바꾸는 값) / 필요한 것(다리 최소 판과 쓰는 조회·명령) / **알아둘 점·한계** / 확인한 범위(시험한 엑셀 판과 못 시험한 것). 화면에 "무료 운영"·"개인 프로젝트" 같은 영구 약속 문구는 쓰지 않는다.

기능 모듈 이름·설명을 고치면 훈수꾼 묶음의 `hunsu.app.json`(`modules`)이 선언에서 자동으로 뽑으므로 따로 고칠 곳이 없다(`name` = 선언 `name`, `summary` = `description`의 **첫 문장**). 그래서 `description`은 **첫 문장에서 하는 일이 끝나게** 쓴다.

## 9. 안전
- **기능 모듈은 코드를 실행하지 못한다.** 선언은 글 틀과 조건 한 줄(`==`·`!=`·`>`·`>=`·`<`·`<=`)만 받고, 괄호·`&&`·함수는 받지 않는다(조건은 거짓으로 본다).
- **명령 인자는 글자로만** 들어간다. `arg.<이름>`의 값은 글 틀로 채워 JSON 글자 칸으로 묶이므로 선언이 JSON 문장을 직접 만들 수 없다.
- **명령은 허용 목록만.** 3-8 `commands`에 없는 명령은 틀이 보내지 않는다.
- **경로 탈출 금지.** 기능 모듈 zip에서 절대 경로·`..`·`\`·`:`가 든 경로는 칼퇴가 풀지 않는다. 판 폴더 이름은 영문·숫자·`.`·`-`·`_` 1~32자만 받는다.
- **실행 파일을 넣지 않는다.** 칼퇴가 기능 모듈 zip에서 확인하는 것은 경로 안전·파일 수·풀린 크기·SHA-256이다. 엑셀 추가기능 zip처럼 `.exe`·`.dll`·`.bat`·`.cmd`·`.vbs`·`.ps1`을 이름으로 거부하는 규칙이 기능 모듈에도 있는지는 확인하지 못했으니, 운영자 검수에서는 같은 기준으로 거부한다고 본다.
- **조회는 읽기 전용이다.** 선택·활성 시트·엑셀 설정을 바꾸지 않고, 경로·개인 정보를 돌려주지 않는다(파일 경로 대신 이름만). 큰 시트에서 느려지지 않게 개수·칸 수 한도를 둔다.
- **쓰기 명령은 실험 기능이다.** 훈수꾼은 사용자가 "실험 기능이며 오류가 생길 수 있다"는 안내를 보고 확인한 뒤에만 보낸다. 모든 `write.` 명령은 `confirm`이 `"1"`이 아니면 엑셀을 바꾸지 않고 **계획**만 돌려준다. 되돌릴 수 있는 명령은 `undoCmd`로 알려 준다. **엑셀 바깥에서 쓴 값은 엑셀의 되돌리기(Ctrl+Z)에 들어가지 않는다**(측정 결과). 그래서 되돌릴 방법은 다리가 직접 둔다(바뀐 칸의 옛 내용을 메모리에 두기).
  기능 모듈이 쓰기 명령을 쓰려면 새 쓰기 명령은 다리에 더해야 하고(5장), 계획 → 확인 → 실행 → 되돌리기 규칙을 지켜야 한다.
- **밖에서 온 값은 믿지 않는다.** 조회 응답도 틀이 한도·형식을 검사한다(256KB 이내, 넘으면 `truncated`). 선언의 글 틀 값이 없으면 `-`로 보이고 예외를 내지 않는다.
- 되돌릴 수 없는 일은 확인을 받는다. 오프라인에서도 돌아야 하며 외부로 데이터를 보내는 기능은 만들지 않는다.
- 비밀값·회사 자료·개인 정보는 선언·README·시험 자료에 넣지 않는다.

## 10. 외부 코드를 쓸 때
- **허용형 라이선스(MIT 등)만.** 원본은 고치지 않고 `vendor`에 두며 출처·커밋(판 고정)·라이선스를 `SOURCES.md`에 적는다.
- 선언형 기능 모듈 자체는 코드가 없어 가져올 외부 코드가 없다. 외부 코드가 필요한 일(예: 엑셀 쪽 JSON 만들기)은 다리나 틀 쪽 이야기이므로 그쪽 PR에서 한다.
- 아이콘은 Fluent UI System Icons(MIT) 같은 허용형 세트에서 고르고 뜻 이름으로만 쓴다. 기능 모듈이 그림 파일을 가져오지 않는다.
- 비공개·회사 자료에서 가져온 그림·글을 넣지 않는다.

## 11. 올리는 방법, 빌드와 시험, 확인 범위

### 11-1. 만들기
1. 훈수꾼 저장소 `modules/hunsu-<이름>/`에 선언 두 파일(+README)을 둔다. 브랜치 이름은 `claude/<범위>-<세부>-<일번호>-<슬러그>`를 권한다(훈수꾼은 범위 코드 `h`).
2. **시험**: 훈수꾼 저장소의 시험은 저장소의 모든 기능 모듈 선언을 읽어 검증한다(id 형식, `shapes`·`place` 맞음, `quick` 키가 실제 설정인지, `view.json` 부품 이름·톤, 기본 자리). `dotnet test`가 통과해야 한다. 클라우드에서도 돌려 볼 수 있다.
3. **확인용 엑셀**: 훈수꾼 저장소에는 모든 기능 모듈을 한 파일에서 확인하는 시나리오 통합 문서(`훈수꾼_확인용.xlsx`)가 있다. 첫 시트에 기능 모듈마다 "어디에서 무엇을 하면 무엇이 보여야 하는지"가 적혀 있다. **새 기능 모듈은 시나리오 한 줄과 필요한 시트를 더한다**(시험이 빠진 기능 모듈을 잡는다). 가짜 자료만 쓴다. 이 문서를 다시 만드는 스크립트는 클라우드에서만 쓰이고, 사용자 PC의 빌드 경로에는 파이썬이 필요 없다.
4. **판 번호**: 훈수꾼 프로그램(`src/`·`modules/`·`addins/`)을 바꾸는 PR은 훈수꾼 판(`Directory.Build.props`)도 올린다(빌드 검사가 있다). 기능 모듈 `version`은 3장 7장대로 따로 올린다. 패치노트(`hunsu.changes.md`) 맨 위도 그날 항목을 쓴다.
5. PR 본문: ① 무엇을 왜 ② 끝난 것 ③ 남은 일과 다음 할 일 ④ **확인한 범위와 못 한 것** ⑤ 관련 결정(이 문서의 장 번호) ⑥ 먼저 읽을 파일 3개 이내. 작업이 끝나거나 멈출 때 `HANDOFF.md`도 고친다.
6. **빌드와 화면 확인은 Windows PC에서만** 된다(엑셀과 WPF 화면). 클라우드에서 확인한 것(선언 읽기·시험)과 PC에서 확인해야 할 것(패널 모양, 엑셀에서 나오는 값)을 PR에 따로 적는다. 화면 모양 확인은 사용자가 한다.

### 11-2. 카탈로그에 올리기 (하위 프로그램 공통 흐름, 공통 계약 8장)
- 기능 모듈은 `catalog.json`의 최상위 `modules`에 `app: "hunsu"`로 올린다. **칼퇴 쪽 받기 규칙은 구현됐으나(받기·해시 검사·안전 풀기) 훈수꾼 기능 모듈이 실제로 올라간 적은 아직 없다.** 첫 기능 모듈을 올릴 때 아래 흐름을 같이 확인한다.
  ```json
  "modules": [
    {"app": "hunsu", "id": "hunsu-errors", "name": "오류 셀", "version": "0.1.000",
     "summary": "지금 시트의 오류 셀을 모아 보여 주고 누르면 그 칸으로 이동합니다.", "author": "ClockOut",
     "url": "https://github.com/sbg3704/ClockOut-Catalog/releases/download/<태그>/hunsu-errors.zip",
     "sha256": "<zip의 SHA-256 소문자 16진수 64자>", "size": 1234, "kind": "module"}
  ]
  ```
  필수 `app`·`id`·`name`(80자 이하)·`version`·`url`(허용 주소의 `.zip`)·`sha256`. 선택 `summary`·`author`·`size`(200MB 이하)·`kind`(`module` 또는 `library`). 같은 `app`에서 `id` 중복 금지. 항목 하나가 틀려도 나머지는 쓰이고 틀린 항목만 건너뛴다.
- **zip 모양**: 맨 위(하위 폴더 없이)에 `<id>.hunsu.json`과 `view.json`(+README). 칼퇴가 `<apps>\hunsu\modules\<id>\<판>\`에 풀고 표시 파일을 더한다. 훈수꾼은 그 폴더에서 `<id>.hunsu.json`을 찾는다.
- **순서**: ① zip을 만든다 → ② SHA-256·크기를 계산한다 → ③ **GitHub Release를 먼저** 올린다 → ④ 그 뒤에 `catalog.json` PR을 머지한다(카탈로그가 먼저 나가면 받을 파일이 없다). 받아도 되는 주소는 이 저장소의 Release와 raw 파일뿐이다.
- 칼퇴가 받은 파일의 SHA-256이 `sha256`과 다르면 지우고 설치하지 않는다. 한 판 = 한 SHA(같은 판을 다시 만들면 해시가 달라지니 판을 올린다).
- **인증**: 운영자가 확인한 id·판·SHA와 일치하는 것만 "인증"으로 보이고, 아니면 **미인증**이라 기본으로 숨겨지며 설치할 때 "인증되지 않은 기능 모듈이며 생기는 문제는 사용자 책임" 경고에 동의해야 한다(칼퇴에서 단계적으로 구현 중). 개발자 모드에서는 내 기능 모듈이 인증 없이도 보인다.
- **정해지지 않은 것(사용자 결정 필요)**: ① 기능 모듈 Release 태그 이름 규칙(하위 프로그램 본체는 `app-hunsu-<판>`, 엑셀 추가기능은 `<id>-<판>`이다. 기능 모듈은 `module-hunsu-<id>-<판>` 같은 모양을 **제안**한다) ② 저장소 쪽 `module.json`(칼퇴의 모듈 저장소 판별용 목록 선언)과 이 카탈로그 `modules` 항목이 앞으로 하나로 합쳐지는지.
- 훈수꾼 본체(`hunsu.zip`)를 올리는 순서는 훈수꾼 저장소의 릴리스 가이드가 정한다(태그 `app-hunsu-<판>`, `--latest=false`, 카탈로그 `apps` 구역 5곳만 수정, SHA 장부). 기능 모듈은 이 흐름과 별개다.

### 11-3. 알려진 한계와 확인 범위
- **화면은 못 봤다.** 이 문서는 소스와 선언 27개를 읽어 쓴 것이고, 새 기능 모듈을 처음부터 만들어 칼퇴로 받아 켜 보는 전체 흐름은 아직 해 보지 못했다(받은 기능 모듈을 읽는 코드와 시험은 있다).
- 부품 중 `toggle`·`input`·`flow`·`tabs`는 이름만 받아 두고 **"준비 중" 자리표시**로 그려진다(함수설명서 2장). 지금 실제로 그려지는 부품은 9개다.
- 기능 모듈이 새 설정 키를 만들 수 없다는 제한(3-7)은 현재 구현의 사실이다. 이 부분이 외부 작성자에게 불편하면 공용에 일반화를 요청한다(훈수꾼 쪽 결정).
- 다리 `errors`는 활성 시트만 본다(요청의 `scope`·`limit`은 아직 받지 않는다). 그 밖의 조회별 한계는 함수설명서 4장의 "한계" 칸.
- 모든 판정은 엑셀 데스크톱판(Windows)이다. 보호된 보기에서는 이벤트와 조회가 막혀 훈수꾼이 쉰다.
- 다리가 없는 엑셀 창(또는 매크로가 막힌 창)에서는 조회가 `bridge_missing`으로 실패하고, 훈수꾼이 알림 영역 풍선으로 한 번 알린다.

## 12. 점검표 (PR 내기 전)
- [ ] `modules/hunsu-<이름>/` 폴더 하나, 폴더 이름 = 선언 id, 선언 파일 이름 `<id>.hunsu.json`
- [ ] 필수 칸을 채웠고(`dependencies`는 `[]`라도 있다), `shapes`에 `panel`·`window` 중 하나가 있고 `place`에 맞는다
- [ ] 선언·`view.json` 각 64KB 이하, 이 문서의 칸만 썼다(지어낸 칸 없음)
- [ ] `data.topic`은 다리 `hello`의 조회 이름이고 `weight`가 알맞다. `dependencies.min_version`이 쓰는 조회·명령의 판 이상이다
- [ ] 단추·목록 줄의 `command`가 모두 `commands` 허용 목록에 있다
- [ ] 색·글꼴을 적지 않고 `tone`만 썼다. 계산·함수·반복 없이 글 틀과 조건만 썼다
- [ ] `quick`의 `key`가 실제 있는 설정 키이고, `hotkey`가 규칙(Ctrl 또는 Alt 포함)을 지킨다
- [ ] 쓰기 명령을 썼다면 계획 → 확인 → 실행 → 되돌리기가 되고 실험 안내를 거친다
- [ ] 같은 일을 하는 기존 기능 모듈이 없다. 새로 짠 부분이 공용에 있어야 할 것이 아니다
- [ ] 비밀값·회사 자료·실행 파일이 없다. 외부 자료는 허용형 라이선스이고 출처를 적었다
- [ ] 확인용 엑셀 시나리오 한 줄을 더했고 가짜 자료만 썼다
- [ ] 판 번호(기능 모듈 `version`, 훈수꾼 판, 패치노트)를 올렸다
- [ ] 클라우드에서 확인한 것과 PC에서 확인해야 할 것을 PR에 나눠 적었다
